# สิ่งที่ลองตอนทดสอบใช้งาน

1. ผู้ดูแลเปิดหน้าตั้งค่า → ทุกช่องมีชื่อสองภาษา ค่าพร้อมหน่วย ช่วงหรือตัวเลือก ค่าเริ่มต้น และสองบรรทัดว่าคืออะไรและปรับแล้วเป็นอย่างไร
2. กรอกค่านอกช่วงสองช่องในแท็บเดียวแล้วบันทึก → ข้อความขึ้นใต้ทั้งสองช่องพร้อมกัน ค่าที่กรอกยังอยู่ และไม่มีค่าไหนถูกบันทึก
3. ตั้งค่าใหม่แล้วใช้ฟีเจอร์นั้นทันทีโดยไม่ restart → ใช้ค่าใหม่ ส่วนงานที่เริ่มไปก่อนบันทึกจบด้วยค่าเดิม
4. ตั้งรหัสผ่าน SMTP แล้วเปิดหน้าใหม่ ดู HTML, คำตอบ API, log และ Activity Log → เห็นแค่ว่าตั้งแล้ว ไม่มีรหัสหรือความยาวของรหัสที่ไหนเลย
5. แก้ port ของ SMTP โดยปล่อยช่องรหัสว่างแล้วบันทึก → port เปลี่ยน รหัสเดิมยังส่งอีเมลได้ แล้วกด Clear และยืนยัน → รหัสหายและ Activity Log บอกแค่ว่าเปลี่ยน
6. ทำ allow-list ที่มีรายการให้ว่าง หรือปิดสวิตช์ OTP แล้วบันทึก → กล่องยืนยันบอกทุกการเปลี่ยนเป็นประโยค กด Cancel แล้วไม่มีอะไรถูกบันทึก
7. สองคนเปิดแท็บเดียวกัน คนแรกแก้ค่าหนึ่งและบันทึก คนที่สองแก้ค่าเดียวกันแล้วบันทึก → คนที่สองเห็นแถบแจ้งพร้อม Reload ค่าของคนแรกยังอยู่ ถ้าแก้คนละค่าบันทึกได้ทั้งคู่
8. ตั้งค่าความปลอดภัยให้หลวมกว่าขอบ → ถูกปฏิเสธพร้อมข้อความบอกขอบ และตั้งให้เข้มขึ้นได้
9. เปลี่ยนค่าหนึ่งแล้วเปิด Activity Log → มีรายการ `SaveSettings` ของแท็บนั้นพร้อมค่าเก่าและค่าใหม่ บันทึกซ้ำโดยไม่เปลี่ยนอะไรแล้วไม่มีรายการเพิ่ม
10. กด Default ข้างช่อง แล้วกด Reset tab → ค่าเริ่มต้นเข้าไปในร่างเท่านั้น ยังไม่บันทึก จนกว่าจะกด Save และความลับไม่ถูกแตะ
11. ผู้ใช้ที่ถือแค่ View เปิดหน้า → อ่านได้ทุกแท็บแต่ไม่มี Save, Cancel, Default, Reset tab หรือ Clear ผู้ใช้ที่ไม่มี View ไม่เห็นเมนูและเปิดด้วย URL ได้แผง no-access
12. แก้ env ของค่าที่ย้ายมาบนจอแล้ว restart → ค่าบนจอไม่เปลี่ยน และมี warning บอกชื่อ env กับคีย์ ไม่มีค่า
13. ตั้ง env ฉุกเฉินที่แพ็กเจ้าของกำหนดแล้ว restart → ระบบใช้ค่าที่ env บังคับ หน้าจอแสดงว่าถูกบังคับ ค่าที่เก็บไม่เปลี่ยน และเอา env ออกแล้วกลับมาใช้ค่าเดิม
14. (test) start บน Production โดยไม่มี `SETTINGS_SECRET_KEY` ขณะ catalog มีความลับ → API ไม่ start ข้อความบอกชื่อ env ไม่มีค่า ส่วนบน Development → start ได้ หน้าตั้งค่าแจ้งว่าไม่มีกุญแจ และบันทึกค่าความลับไม่ได้
15. (test) เปลี่ยนกุญแจพร้อมใส่กุญแจเก่าใน `SETTINGS_SECRET_KEY_PREVIOUS` → ความลับยังอ่านได้และถูกเขียนใหม่ด้วยกุญแจใหม่ ไม่มีกุญแจเก่า → ระบบยัง start และช่องนั้นขอให้กรอกใหม่
16. (test) รุ่นใหม่แคบช่วงของคีย์ที่เก็บค่าเกินไว้ → ตอน start ค่าถูกปรับเป็นปลายช่วงที่ใกล้ที่สุด มีรายการ `SaveSettings` โดย System และ warning บอกคีย์
17. (test) เรียก API ตรงเพื่อบันทึกการเปลี่ยนที่ต้องยืนยันโดยไม่ส่งการยืนยัน → ตอบ 400 `VALIDATION_FAILED` บนคีย์นั้นพร้อมข้อความว่าต้องยืนยัน และไม่บันทึก
