## 6. คำตอบของผู้ใช้ (2026-11-26)

ถามทีละข้อพร้อมตัวเลขจาก §3 แล้วได้คำตอบ `1 a, 2 a, 3 a, 4 b` ส่วนคำถามว่าจะทำเป็น plugin ใหม่หรือไม่ ผู้ใช้ตกลงให้ปรับใน mflow เดิม

1. **push:** push branch ที่อยู่ รวมถึง main ทันทีหลังทุก commit โดยไม่ถามและไม่ใช้ force merge ยังถามเหมือนเดิม ผู้ใช้เพิ่มเงื่อนไขภายหลังว่า เมื่องานมีเรื่อง deploy ให้ตัดสิน (rebuild stack ที่รันอยู่, migration บนฐานข้อมูลที่ใช้ร่วมกันหรือของจริง) ให้รอ push แล้วถามบรรทัดเดียวว่า a) push อย่างเดียว หรือ b) push + deploy ถ้าไม่มี deploy ให้ push เลยโดยไม่ถาม
2. **ขั้นถัดไป:** หลัง approve เอกสาร discuss หรือ change request ให้ Claude ทำ propose และ apply ต่อเองโดยไม่ถาม หยุดเฉพาะเมื่อมีคำถามเรื่องแก้ยาก หัวข้อ discuss ใหม่ให้ถามหนึ่งบรรทัด แล้ว Claude ทำเองเมื่อผู้ใช้ตอบ "ทำ" ส่วน test, test-pr, review, e2e, night, apply-all และ checks ยังรอคำสั่งของผู้ใช้
3. **discuss:** ข้อ `แก้ทีหลังได้` ให้ Claude ตอบเองในเอกสาร และเขียนกำกับว่าเป็นตัวเลือกของ Claude ผู้ใช้ตอบเฉพาะข้อ `แก้ยาก` และส่งคำตอบพร้อม approve ในบรรทัดเดียวได้
4. **agent อื่น:** Claude สั่ง Codex และ agy เองสำหรับงานอ่านอย่างเดียว (consult, challenge, analyze, review) ตรวจว่ามีรายงานกลับมาจริง แล้วประเมินผลให้ ข้อนี้เปลี่ยน FR-101 เฉพาะงานอ่านอย่างเดียว งานเขียนโค้ดยังใช้ worktree และ checks runner ที่ผู้ใช้เปิดเอง

สองเรื่องคงไว้ตามหลักฐาน โดยไม่ถามผู้ใช้:
- ตาราง foundation แบบเต็มก่อนเริ่ม: ผู้ใช้เปลี่ยนคำตอบที่ตารางนี้จริง
- บรรทัด a/b เรื่อง merge หลัง apply: ผู้ใช้เลือกต่างจากคำแนะนำ 4 ครั้ง
