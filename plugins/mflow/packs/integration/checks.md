# integration checks

สิ่งที่ลองตอนทดสอบใช้งาน แต่ละข้อเป็น test หรือ acceptance criterion ได้

1. เปิดระบบด้วยโหมดปลอม ทำงานธุรกิจที่เขียนออก: รายการถูกบันทึก แถวในคิวเป็น Pending แล้วตัวส่งส่งเป็น Sent และจอติดตามเห็นครั้งที่สำเร็จ
2. สั่งของปลอมให้ตอบ 500 ครั้งถัดไป แล้วทำงานเขียนออก: ส่งแค่ครั้งเดียวในการเรียกนั้น แถวกลับเป็น Pending พร้อมเวลาครั้งถัดไป ตอนส่งซ้ำใช้คีย์กันซ้ำเดิม
3. สั่งของปลอมให้ตอบ 422: แถวเป็น Failed ไม่ถูกส่งซ้ำเอง กด Re-send พร้อมเหตุผลแล้วส่งได้ และ Activity Log มีเหตุผลนั้น
4. ปิดโปรเซส API ทันทีหลัง commit งานเขียนออก แล้วเปิดใหม่: แถวยังอยู่และถูกส่ง ไม่หาย ไม่ซ้ำ
5. ทำให้การบันทึกงานธุรกิจล้มหลังเพิ่มแถวคิว: ไม่มีแถวเหลือ และไม่มีอะไรออกไป
6. สั่งของปลอมให้ตอบหมดเวลาโดยที่งานเกิดขึ้นแล้วที่อีกฝั่ง และอีกฝั่งไม่รับคีย์กันซ้ำ: ระบบอ่านผลก่อน แล้วเป็น Sent โดยไม่เขียนซ้ำ
7. สั่งของปลอมให้ตอบ 503 ระหว่างรอบดึงเข้า: รอบหยุดทันที รายการที่รับแล้วคงอยู่ cursor ไม่ขยับ และรอบถัดไปอ่านช่วงเดิมซ้ำ
8. เรียก API ที่ต้องใช้ระบบภายนอกขณะของปลอมตอบ 503: ได้ 503 `<SYSTEM>_UNAVAILABLE` พร้อมรหัสอ้างอิง และหน้าที่ไม่ใช้ระบบนั้นยังทำงาน
9. หารหัสอ้างอิงที่ผู้ใช้เห็นบนจอติดตาม: เจอการเรียกนั้นพร้อมผู้เรียก เวลา และรหัสตอบกลับ
10. ทำให้ token หมดอายุกลางรอบ: ได้ 401 ครั้งเดียว มีการขอ token ใหม่หนึ่งครั้ง งานเดินต่อ และ log มีทั้งสามการเรียก
11. ดู `integration_call_log` ของการขอ token และเส้นที่มีรหัสผ่านใน body: ไม่มีรหัสผ่าน ไม่มี token และไม่มี header เลย
12. ตั้ง address ของระบบเป็น host ที่ไม่อยู่ใน `INTEGRATION_ALLOWED_HOSTS`: บันทึกไม่ได้ และเมื่อแก้ตรงในฐานข้อมูล การเรียกถูกปฏิเสธโดยไม่เปิดการเชื่อมต่อ
13. เปิด API ใน Production ด้วย `<SYSTEM>_MODE=fake`: ไม่ start พร้อมชื่อค่า และตัวสั่งของปลอมตอบ 404 ในโหมด live
14. กด Test connection ด้วยรหัสผ่านผิด: เห็นผลล้มและรหัส 401 ภายในเวลาที่กำหนด ไม่มีค่าตั้งในคำตอบ และ Activity Log มีการทดสอบ
15. ยิง webhook ลายเซ็นถูก: แถว inbox หนึ่งแถว ตอบ 200 และงานธุรกิจเกิดหนึ่งครั้ง ยิงซ้ำ event id เดิม: ตอบ 200 และไม่เกิดซ้ำ ลายเซ็นผิดหรือเวลาเก่าเกินกำหนด: ตอบ 401 และไม่มีแถว
16. ทำให้ระบบหนึ่งตอบล้มติดกันครบจำนวนที่กำหนดจากปุ่มของผู้ใช้: อีเมลแจ้งเตือนหนึ่งฉบับ ไม่ซ้ำในช่วงที่กำหนด และเมื่อกลับมาปกติมีหนึ่งฉบับ
17. เปิดจอติดตามด้วยผู้ถือ View ที่ขอบเขตข้อมูลเป็นรายชื่อ: เห็นตัวเลขรวม ไม่เห็นแถวรายเอกสาร ไม่มีปุ่ม Re-send
18. ดึงย้อนหลังด้วยมือจากเวลาที่เลือก: รายการเดิมไม่ซ้ำ cursor ไม่เปลี่ยน
19. (เมื่อมีไฟล์) ส่งไฟล์ขณะอีกฝั่งล่ม: แถวรอพร้อม key ของไฟล์ เนื้อไฟล์ไม่อยู่ใน payload และ log
20. (test) เพิ่มการเรียก HTTP ใน Service: architecture test ล้มและบอกตำแหน่ง
21. (test) ชุดทดสอบสัญญาโดยไม่มีค่าใน env: ถูกข้ามทั้งชุด ไม่นับว่าล้ม
