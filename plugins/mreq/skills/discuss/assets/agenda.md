รายการนี้แนะนำว่าเรื่องไหนควรคุยให้ตรงกันก่อนทำ UI kit หน้าจอ หรือส่งมอบ เพราะเอกสารลูกค้ายังตีความได้หลายแบบ ขัดกันเอง หรือยังไม่ได้บอกทั้งที่ระบบต้องใช้ เป็นคำแนะนำเท่านั้น จะคุยเรื่องไหนก่อน หรือไม่คุยเรื่องไหนเลยก็ได้ ไม่มีคำสั่งไหนรอรายการนี้

- เริ่มคุยหัวข้อ: `/mreq:discuss <slug>` เช่น `/mreq:discuss tech-stack`
- ไม่คุยหัวข้อไหน: เขียน `ข้าม: <เหตุผล>` ในช่องสถานะ หรือสั่ง `/mreq:discuss agenda skip <slug> <เหตุผล>`
- **ทบทวน:** ในช่อง "ทำไมควรคุย" แปลว่าข้อมูลที่เข้ามาใหม่เปลี่ยนเรื่องที่อนุมัติไปแล้ว ควรเปิดเอกสาร discuss ฉบับใหม่ของหัวข้อนั้น
- ช่องสถานะอัปเดตเองจากเอกสาร discuss: ยังไม่เริ่ม, กำลังคุย `NN`, อนุมัติแล้ว `NN`, ยกเลิก `NN`, แทนแล้ว `NN`
- สี่หัวข้อแรกเป็นพื้นฐานของการสร้างระบบ มีในทุกโปรเจกต์ เพราะ UI kit และทุกอย่างหลังจากนี้ใช้คำตอบของมัน

| # | หัวข้อ | ทำไมควรคุย | ควรคุยก่อน | สถานะ |
|---|---|---|---|---|
| 1 | Tech stack: แอป เฟรมเวิร์ก library ฐานข้อมูล Docker (`tech-stack`) | ระบบมีแอปอะไรบ้าง (web หลังบ้าน, web หน้าบ้าน, API, mobile) แต่ละตัวใช้เทคโนโลยีอะไร ใช้ library ไหน (open source และฟรี ตรวจ licence แล้ว) ฐานข้อมูล, Docker, environment และตัวเสริมที่ใส่ภายหลังได้ UI kit ต้องรู้ว่ามีแอปที่มีหน้าจอกี่ชนิด ถ้าเลือกผิดต้องทำ kit และหน้าจอใหม่ | ก่อน `/mreq:theme` |  |
| 2 | โครงสร้างโค้ดและโฟลเดอร์ (`code-structure`) | ชื่อโปรเจกต์ในโค้ด ชื่อแอปแบบ `<ชื่อโปรเจกต์>.Web.Backend` / `.Web.Frontend` / `.Api` โครง repo และ solution แยกตาม layer และทิศทางการอ้างอิงระหว่าง project ถ้าตั้งผิดตอนเริ่ม ผู้สร้างต้องย้ายไฟล์ทั้ง repo ภายหลัง | ก่อน `/mreq:theme` |  |
| 3 | คุณภาพที่ต้องการ: ผู้ใช้ ปริมาณข้อมูล ความเร็ว การสำรองข้อมูล (`nfr`) | จำนวนผู้ใช้และข้อมูลเป็นหลักฐานที่ tech stack ใช้ตัดสินว่าต้องมี cache หรือ queue ไหม ส่วนอุปกรณ์และภาษาที่ต้องรองรับกำหนดหน้าตาของ UI kit | ก่อน `/mreq:theme` |  |
| 4 | ความปลอดภัยและข้อมูลส่วนบุคคล (`security-privacy`) | วิธี login, SSO, MFA และ PDPA (ข้อมูลส่วนบุคคลที่เก็บ ความยินยอม ระยะเวลาเก็บ) กระทบหน้าจอ login, การเก็บข้อมูล และการออกแบบฐานข้อมูล ถ้ามาคิดทีหลังต้องแก้หลายส่วน | ก่อนส่งมอบครั้งแรก |  |
