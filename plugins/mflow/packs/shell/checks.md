# สิ่งที่ลองตอนทดสอบใช้งาน

1. เข้าระบบด้วยผู้ใช้ที่ถือคีย์ View ของหน้าเดียว → เมนูมีรายการเดียว ไม่มีกลุ่มเมนูว่าง และพิมพ์ address ของหน้าอื่นแล้วไม่เห็นข้อมูลของหน้านั้น
2. ย่อหน้าต่างจากกว้างสุดลงจนแคบ → sidebar เปลี่ยนจากเมนูเต็ม เป็นแถบไอคอน แล้วเป็น drawer ที่เปิดด้วย ☰ และปิดด้วย Esc โดยหน้าไม่เลื่อนข้าง
3. เปิดเมนูผู้ใช้ทุกพอร์ทัล → มี Sign out เสมอ และมี Profile เฉพาะพอร์ทัลที่มีหน้า Profile
4. ตั้งเครื่องเป็นเขตเวลาอื่นและภาษาไทย แล้วเปิดรายการที่มีเวลาใกล้เที่ยงคืน → วันที่และเวลาตรงกับเขตเวลาของระบบ และปีเป็นแบบที่โปรเจกต์เลือก ไม่ใช่ตาม locale ของเครื่อง
5. ดูยอดเงินในตาราง → คั่นหลักพัน ทศนิยมครบ ชิดขวา และยอดติดลบมีเครื่องหมายลบ
6. ในรายการ: กรอง เรียง ไปหน้า 2 แล้วเปลี่ยนจำนวนแถว → กลับไปหน้า 1 และ address เก็บค่าทั้งหมด เปิด address นั้นในแท็บใหม่ได้แถวเดิม
7. กรองจนไม่พบ แล้วทำให้การอ่านล้มเหลว → เห็นข้อความไม่พบพร้อมล้างตัวกรอง และข้อผิดพลาดพร้อมลองใหม่ ไม่ใช่ข้อความว่าง
8. ในช่องเลือกระเบียน: ค้น เลือก แล้วกดยกเลิก → ช่องคงค่าเดิม ส่วนยืนยันแล้วช่องแสดงชื่อที่เลือกพร้อมปุ่ม ×
9. อนุมัติเอกสารจากหน้า 2 ของส่วนประวัติ → ตารางกลับหน้า 1 และรายการอนุมัติอยู่บนสุดพร้อมสถานะก่อน → หลัง
10. บันทึกฟอร์มที่ช่องบังคับว่าง แล้วบันทึกด้วยรหัสที่ซ้ำ → ข้อผิดพลาดแรกขึ้นใต้ช่องก่อนส่ง ข้อผิดพลาดจาก server ขึ้นใต้ช่องรหัส และค่าที่กรอกยังอยู่
11. แก้ฟอร์มแล้วกดเมนูอื่น แล้วกดโหลดหน้าใหม่ → ครั้งแรกขึ้น dialog ยืนยันของ kit ครั้งที่สองขึ้นคำถามของ browser และฟอร์มที่ไม่ได้แก้ออกได้ทันที
12. ดับเบิลคลิกปุ่มบันทึกของรายการใหม่ → ได้เอกสารเดียว
13. ลบรายการ → dialog บอกเลขหรือชื่อของรายการ focus อยู่ที่ยกเลิก ลบสำเร็จแล้วขึ้น toast ที่หายเอง
14. เปิด address ที่ไม่มี และปล่อยให้เซสชันหมดแล้วกดในหน้า → ได้หน้า 404 ใน layout พร้อมลิงก์หน้าแรก และได้หน้าเข้าระบบที่บอกว่าเซสชันหมด เข้าใหม่แล้วกลับหน้าเดิม
15. (test) build ของ production แล้วเปิด address ของ style guide → ได้ 404
16. (test) ใส่ค่าสีตายตัวหรือ inline style ในไฟล์หน้าจอ แล้วรันการตรวจ → การตรวจล้มและบอกชื่อไฟล์
