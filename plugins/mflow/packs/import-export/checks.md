# import-export checks

สิ่งที่ลองตอนทดสอบใช้งาน แต่ละข้อเป็น test หรือ acceptance criterion ได้

1. ดาวน์โหลดแม่แบบของ `{import_target}` แล้วอัปโหลดกลับโดยไม่แก้: ไฟล์ผ่านการตรวจโครงสร้าง และหน้าจอบอกว่าไม่มีแถวให้นำเข้า ยืนยันไม่ได้
2. เพิ่มคอลัมน์ในนิยาม แล้วดาวน์โหลดแม่แบบใหม่: มีคอลัมน์นั้น ตัวอ่านรับคอลัมน์นั้นโดยไม่ต้องแก้ที่อื่น
3. อัปโหลด `.xls` ไฟล์ PDF ที่เปลี่ยนชื่อเป็น `.xlsx` และไฟล์ `.xlsx` ที่แตกแล้วใหญ่เกินเพดาน: ทั้งสามถูกปฏิเสธพร้อมข้อความ ไม่มีชุดนำเข้า และหน่วยความจำของ server ไม่พุ่งตามขนาดไฟล์ที่แตก
4. เปลี่ยนชื่อชีทและสลับคอลัมน์ของไฟล์ที่ถูกต้อง: ผลเหมือนไฟล์เดิมทุกอย่าง
5. เพิ่มคอลัมน์ชื่อ `Remark` ในไฟล์ ไฟล์อีกชุดขาดคอลัมน์บังคับกรอก และไฟล์ที่มีชีทซ่อนซึ่งมีหัวเหมือนชีทข้อมูล: ทั้งหมดถูกปฏิเสธพร้อมชื่อชีทและคอลัมน์
6. ไฟล์ที่มีแถวผิดหลายแบบ: หน้าผลตรวจแสดงทุกแถวที่ผิดพร้อมเลขแถวตรงกับ Excel คอลัมน์ และเหตุผล แถวหนึ่งผิดสองช่องขึ้นสองข้อ และรายงาน CSV ที่ดาวน์โหลดเปิดใน Excel แล้วอ่านไทยได้ มีครบทุกข้อ
7. ไฟล์ที่มีแถวผิดหนึ่งแถว: หน้าผลตรวจต้องเตือนจำนวนแถวที่จะไม่ถูกนำเข้า และดูแถวนั้นพร้อมเหตุผลได้ กดยกเลิกแล้วไม่มีอะไรถูกบันทึก อัปโหลดใหม่แล้วกดยืนยัน กล่องต้องบอกจำนวนที่จะไม่ถูกนำเข้า และบันทึกเฉพาะแถวที่ผ่าน แถวผิดยังอยู่ในรายงาน ไฟล์ที่ผิดทุกแถวต้องกดยืนยันไม่ได้
8. วันที่ทั้งหกแบบ: เซลล์วันที่ ค.ศ. เซลล์วันที่แสดงแบบ พ.ศ. ข้อความ `15/01/2569` เซลล์วันที่ที่มีปี 2569 เซลล์ตัวเลขเปล่า และข้อความ `29/02/2567`: ได้วันที่ถูกห้าแบบ แบบตัวเลขเปล่าเป็นแถวผิด
9. เปลี่ยนเครื่องที่รัน API เป็นภาษาไทย แล้วนำเข้าไฟล์เดิม: วันที่และตัวเลขที่อ่านได้ไม่เปลี่ยน
10. คอลัมน์รหัสที่พิมพ์ `00123` ในแม่แบบ และรหัสเลขล้วนใน Excel ที่ไม่ได้ตั้งเป็น Text: แบบแรกได้ `00123` แบบหลังไม่มี `.0` และถ้านิยามกำหนดความยาว แถวที่เสียศูนย์เป็นแถวผิด ระบบไม่เติมศูนย์
11. จำนวนเงินที่แสดงปัดเศษ เซลล์สูตรที่มีค่าบันทึกไว้ เซลล์สูตรที่ไม่มีค่าบันทึก และเซลล์ `#N/A`: ได้ค่าที่เก็บจริง ค่าที่บันทึกไว้ ค่าว่าง และแถวผิดตามลำดับ
12. ไฟล์ที่มี `{match_key}` เหมือนกันสองแถว: ทั้งสองแถวเป็น Duplicate ในรายงาน
13. นำเข้าแถวที่แก้รายการเดิมโดยปล่อยบางช่องว่าง: ค่าเดิมของช่องที่ว่างไม่เปลี่ยน คอลัมน์ที่นิยามไม่ให้แก้ไม่เปลี่ยน
14. ผู้ใช้ที่มีขอบเขตแค่บางส่วน นำเข้าแถวนอกขอบเขตทั้งแบบใหม่และแบบแก้ของเดิม: เป็นแถวผิด Outside your scope ไม่เห็นข้อมูลของรายการนั้น และมี `AccessDenied` หนึ่งรายการต่อการตรวจ
15. ถือผลตรวจไว้ ให้อีกคนสร้างรายการเดียวกันบนจอ แล้วกดยืนยัน: ได้ `IMPORT_CHANGED` ไม่มีอะไรถูกบันทึก และหน้าจอให้ตรวจใหม่
16. ทำให้การบันทึกล้มกลางทาง: ไม่มีรายการของไฟล์เหลืออยู่ และชุดยังรอยืนยัน
17. อัปโหลดไฟล์ใหญ่กว่าขีดงานเบื้องหลัง: หน้าจอแสดงความคืบหน้า ปิดหน้าแล้วกลับมาดูได้ และระหว่างนั้นอีกคนนำเข้าข้อมูลชนิดเดียวกันได้ `IMPORT_IN_PROGRESS` ส่วนชุดที่รอยืนยันไม่กันคนอื่น
18. ยกเลิกชุดที่ตรวจจบแล้ว: สถานะเป็น `Cancelled` ไม่มีรายการถูกบันทึก ยืนยันต่อไม่ได้ และ Activity Log ไม่มีรายการใหม่
19. ยืนยันไฟล์ที่สร้าง 90 รายการและแก้ 10 รายการ: Activity Log มีรายการ `Import` หนึ่งรายการ พร้อมชื่อไฟล์ sha256 จำนวน และค่าเก่าค่าใหม่ ผู้ทำคือคนที่กดยืนยัน แม้งานรันเบื้องหลัง
20. เลื่อนนาฬิกาเกินอายุ: งานล้างลบชุด แถว และไฟล์ต้นฉบับ ข้อมูลที่บันทึกแล้วไม่เปลี่ยน และ Activity Log ไม่มีรายการใหม่
21. ส่งออก `{list}` ที่กรองแล้ว ด้วยผู้ใช้ที่มีขอบเขตบางส่วน: ไฟล์มีเฉพาะแถวที่เห็นบนจอครบทุกหน้า เรียงตามจอ ไม่มีคอลัมน์หรือชีทซ่อน
22. รายชื่อที่มีค่า `=1+1`, `+66812345678`, `-5` และ `@x` ในคอลัมน์ข้อความ ส่งออกเป็น `.xlsx` และรายงาน CSV: เปิดแล้วไม่มีสูตรทำงาน แก้เซลล์แล้วก็ไม่กลายเป็นสูตร ส่วนจำนวนเงินติดลบในคอลัมน์ตัวเลขยังเป็นตัวเลข
23. ส่งออกเกินเพดาน: ได้ `EXPORT_TOO_LARGE` พร้อมจำนวนแถว กดซ้ำระหว่างงานเบื้องหลังได้งานเดิม ไม่มีงานที่สอง
24. เปิดลิงก์ไฟล์ของคนอื่น และลิงก์ที่หมดอายุ: ได้ 404 ทั้งคู่ หลังงานล้างไฟล์หายจากที่เก็บ และไม่มี URL ของที่เก็บไฟล์ในคำตอบใด
25. ส่งออก `{list}` ที่กำกับว่ามีข้อมูลส่วนบุคคล: Activity Log มี `Export` หนึ่งรายการ ดาวน์โหลดซ้ำไม่เพิ่ม ส่วน `{list}` ที่ไม่กำกับไม่ลง
26. (test) เพิ่มคอลัมน์รหัสผ่านในนิยามส่งออก: test ล้มและบอกคอลัมน์ ไฟล์ที่ส่งออกมีชื่อ `<list>_<yyyyMMdd-HHmm>.xlsx` ไม่มีค่าจากตัวกรอง
