# สิ่งที่ลองตอนทดสอบใช้งาน: permission

1. ผู้ใช้ใน role ที่มีแค่ View ของหน้าจอ เรียก API อนุมัติของหน้าจอนั้นตรงๆ: ได้ 403 `ACCESS_DENIED` ข้อมูลไม่เปลี่ยน และ Activity Log มีรายการที่ถูกปฏิเสธพร้อมคีย์
2. พิมพ์ URL ของหน้าจอที่ role ไม่มี View: เห็นแผง no-access ไม่มีข้อมูลของหน้าจอ และ API เบื้องหลังตอบ 403
3. ถอน Manage ของ role ระหว่างที่สมาชิกยังเข้าระบบอยู่: สมาชิกยังกดได้จนออกจากระบบ เข้าใหม่แล้วปุ่มหายไป
4. เปลี่ยนผู้ใช้ไป role อื่นระหว่างที่เขาใช้งาน: request ถัดไปของเขาตอบ 401 และเข้าใหม่ได้เมนูของ role ใหม่
5. เปิดระเบียนที่อยู่นอกขอบเขตด้วย URL: ได้ 404 เหมือนระเบียนที่ไม่มีอยู่ และ Activity Log มี `AccessDenied` พร้อมรหัส
6. สร้าง role ใหม่แล้วให้ View ของหน้ารายการที่มีขอบเขต: สมาชิกเห็นหน้าแรกกับ Help และรายการว่างจนกว่าจะตั้งขอบเขต
7. ผู้แก้ที่มีขอบเขตไม่ครบ ให้รหัสที่อยู่นอกขอบเขตของตัวเองแก่ role อื่น หรือตั้ง "ทั้งหมด": บันทึกไม่ได้ ได้ข้อผิดพลาดที่ช่องนั้น
8. ติ๊ก Manage ของหน้าจอหนึ่ง: View ติ๊กตาม เอา View ออก: ช่องอื่นของหน้าจอนั้นออกทั้งหมด
9. เพิ่ม endpoint ใหม่ที่ไม่ประกาศสิทธิ์ หรือ query ที่ปิด filter ขอบเขต: architecture test ล้มและบอกชื่อ
10. migration แยกช่องสิทธิ์บนฐานข้อมูลที่มี role อยู่แล้ว: ทุก role ที่ถือช่องเดิมได้ช่องใหม่ ไม่มีใครเสียปุ่ม และ Activity Log มีหนึ่งรายการต่อสิทธิ์ที่เพิ่ม ผู้ทำคือระบบ
11. ในโหมด prototype สลับผู้ใช้จาก banner: ไม่ถามรหัส เมนูเปลี่ยนตาม role ของบัญชีที่เลือก และ Activity Log มี `Login` ที่บอกว่าเป็นการสลับ
12. ถ้ามี `{org_portal}`: แก้หรือลบ `{org_admin}` ได้ 409 `ORG_ROLE_LOCKED` และถอนเมนูออกจาก org role ระหว่างที่บัญชีใช้งาน request ถัดไปตอบ 401
13. เปิดหน้าของ role จากรายการ: ตารางสิทธิ์มีคอลัมน์ ดู จัดการ อนุมัติ-ไม่อนุมัติ นำเข้า ส่งออก หน้าจอที่ไม่มี action ของคอลัมน์นั้นแสดง "—" ไม่มีช่องให้ติ๊ก และตารางผู้ใช้ใต้ตารางสิทธิ์ตรงกับจำนวนผู้ใช้ในรายการ role
14. ติ๊ก Export ของหน้ารายงานให้ role ที่มีแค่ View: ผู้ใช้ใน role เข้าใหม่แล้วเห็นปุ่มส่งออก แต่ยังไม่เห็นปุ่มแก้หรืออนุมัติ
