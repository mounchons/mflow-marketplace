# เอกสาร discuss

หนึ่งไฟล์ต่อหนึ่งหัวข้อ ชื่อ `NN-<slug>.md` เขียนโดย `/mreq:discuss` แต่ละไฟล์บอกว่า Claude เข้าใจเรื่องนั้นอย่างไร หรือเสนอแบบอะไร (tech stack, โครงโค้ด, คุณภาพที่ต้องการ, ความปลอดภัย …) ให้คุณตรวจก่อนที่ UI kit หน้าจอ หรือการสร้างจริงจะพึ่งมัน

ตอบในไฟล์ได้ (พิมพ์ตัวอักษรของตัวเลือกหลัง `**เลือก:**` หรือเขียนบรรทัดที่ขึ้นต้นด้วย `> ความเห็น:`) หรือตอบในแชตด้วย `/mreq:discuss NN <สิ่งที่อยากแก้>` เมื่อไม่มีอะไรค้าง สั่ง `/mreq:discuss NN approve` เพื่อนำข้อที่ตกลงไปใส่ใน AGENTS.md, `mreq/project/vision.md` และ `mreq/project/followups.md` แล้วล็อกไฟล์ไว้เป็นบันทึกเหตุผล

`AGENDA.md` แนะนำว่าหัวข้อไหนควรมีเอกสาร ทำไม และควรคุยก่อนขั้นไหน ช่องสถานะอัปเดตเองจากเอกสาร เป็นคำแนะนำเท่านั้น คุยหัวข้อไหนก่อนก็ได้ หรือข้ามด้วย `ข้าม: <เหตุผล>` ในช่องสถานะ

คำตอบและการอนุมัติของคุณถือเป็นของลูกค้า ไม่มีอะไรในนี้ที่ต้องรอลูกค้ายืนยันอีก ทำก่อน ทดสอบใช้งาน แล้วปรับเพิ่ม ถ้าเปลี่ยนใจหลังอนุมัติ ให้เขียนเอกสารฉบับใหม่ในหัวข้อเดิมมาแทน
