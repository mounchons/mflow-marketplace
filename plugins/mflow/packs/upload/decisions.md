# upload: ข้อที่ตอบไว้แล้ว

### UPL-D01: ระบบรู้จักไฟล์ชนิดไหนบ้าง
- **คำตอบ:** ชุดเดียวที่ระบบตรวจเนื้อไฟล์ได้: .pdf .doc .docx .xls .xlsx .ppt .pptx .csv .txt .jpg .jpeg .png .gif .webp ผู้ดูแลเลือกชนิดที่รับได้จากชุดนี้เท่านั้น ไฟล์บีบอัด (.zip .rar .7z) ไฟล์รันได้และ script (.exe .bat .js .ps1) ไฟล์หน้าเว็บ (.html .svg .xml) และ Office ที่มี macro (.docm .xlsm .pptm) ไม่อยู่ในชุด จึงรับไม่ได้เสมอ
- **เหตุผล:** ชนิดที่อยู่ในชุดต้องมีวิธีตรวจเนื้อไฟล์ ชนิดที่เปิดแล้วรันโค้ดได้หรือซ่อนไฟล์อื่นไว้ข้างในไม่ควรมีทางเข้ามาเลย แม้ผู้ดูแลติ๊กผิด
- **ถ้าผิด:** แก้ทีหลังได้ — เพิ่มชนิดเข้าชุดพร้อมวิธีตรวจใน change ถัดไป
- **ถามเมื่อ:** เอกสารลูกค้าต้องรับชนิดไฟล์นอกชุด เช่น ZIP, ไฟล์ CAD หรือวิดีโอ
- **ตัวเลือกอื่น:** b) เพิ่มชนิดที่ลูกค้าขอเข้าชุด พร้อมวิธีตรวจเนื้อไฟล์ของชนิดนั้น c) รับไฟล์บีบอัดโดยไม่เปิดดูข้างใน และสแกนไวรัสทุกไฟล์ (UPL-D15 ต้องเป็นสแกน)

### UPL-D02: ชนิดที่รับจริงตั้งที่ไหน
- **คำตอบ:** รายการเดียวของทั้งระบบ `upload.extensions` บนหน้าตั้งค่าระบบ (แพ็ก settings) ติ๊กจากชุดของ UPL-D01 อย่างน้อยหนึ่งชนิด เปลี่ยนแล้วมีผลกับไฟล์ถัดไป ไฟล์ที่รับไว้แล้วไม่ถูกแตะ
- **เหตุผล:** ลูกค้าเพิ่มหรือตัดชนิดไฟล์ได้เองโดยไม่ต้อง deploy และกติกาเดียวอธิบายผู้ใช้ได้ง่าย
- **ถ้าผิด:** แก้ทีหลังได้ — แยกรายการเป็นหลายค่าใน change ถัดไป
- **ถามเมื่อ:** ระบบมีหลาย `{portal}` ที่ต้องรับชนิดไฟล์ต่างกัน หรือช่องแนบบางช่องต้องรับเฉพาะรูป
- **ตัวเลือกอื่น:** b) รายการแยกต่อ `{portal}` บนหน้าตั้งค่า c) รายการแยกต่อช่องแนบไฟล์ กำหนดในโค้ด ไม่อยู่บนจอ

### UPL-D03: ไฟล์ใหญ่ได้แค่ไหน และรายการหนึ่งมีได้กี่ไฟล์
- **คำตอบ:** ไฟล์ละไม่เกิน `upload.max_file_mb` MB หนึ่งคำขอส่งหนึ่งไฟล์ `{record}` หนึ่งรายการมีไฟล์ที่ยังผูกอยู่ไม่เกิน `upload.max_files_per_record` ไฟล์ และรวมกันไม่เกิน `upload.max_record_mb` MB ทั้งสามค่าอยู่บนหน้าตั้งค่า ปรับได้ในช่วงของ params และไม่เกินเพดานคำขอของ server `upload.request_limit_mb` ที่ตั้งตอน deploy
- **เหตุผล:** หนึ่งไฟล์ต่อคำขอทำให้ข้อผิดพลาดชี้ไฟล์ได้ตรงตัว และขีดจำกัดต่อรายการกันพื้นที่เต็มจากรายการเดียว
- **ถ้าผิด:** แก้ทีหลังได้ — เป็นค่าตั้งระบบ ส่วนเพดานของ server เปลี่ยนตอน deploy
- **ถามเมื่อ:** เอกสารลูกค้าระบุขนาดหรือจำนวน หรือต้องรับไฟล์ใหญ่กว่า 100 MB
- **ตัวเลือกอื่น:** b) จำกัดขนาดต่อไฟล์อย่างเดียว ไม่จำกัดต่อรายการ c) ไฟล์ใหญ่อัปโหลดเป็นช่วงตรงไปที่เก็บไฟล์ (resumable upload)

### UPL-D04: ตรวจอะไรก่อนรับไฟล์
- **คำตอบ:** ตรวจที่ server ทุกครั้ง: นามสกุลสุดท้ายอยู่ใน `upload.extensions` (ไม่สนตัวพิมพ์) ไฟล์มากกว่า 0 byte และเนื้อไฟล์ (magic bytes) เป็นชนิดเดียวกับนามสกุล .docx .xlsx .pptx ต้องเป็น zip ที่มีส่วนของ Office ไม่ใช่ zip เปล่า .csv .txt ต้องเป็นข้อความที่ไม่มี byte ศูนย์ ชนิดที่เก็บคือชนิดที่ตรวจได้ ไม่ใช่ Content-Type ที่ browser ส่งมา ไม่ผ่านข้อใดก็ไม่เก็บอะไรเลย
- **เหตุผล:** นามสกุลและ Content-Type ปลอมได้ง่าย การตรวจฝั่ง browser ข้ามได้ ส่วนเนื้อไฟล์บอกชนิดจริง
- **ถ้าผิด:** แก้ยาก — ไฟล์ที่รับเข้ามาผิดชนิดแล้วไล่ตามหาและลบทีหลังยาก
- **ถามเมื่อ:** ไม่ถาม

### UPL-D05: เก็บไฟล์ในชื่ออะไร และชื่อเดิมใช้ทำอะไร
- **คำตอบ:** เก็บด้วย key สุ่มที่ระบบสร้าง ไม่มีส่วนใดของชื่อที่ผู้ใช้ส่งมา ชื่อเดิมเก็บไว้แสดงและเป็นชื่อตอนดาวน์โหลดเท่านั้น หลังล้าง: ตัด path (ทั้ง `/` และ `\`) ตัดอักขระควบคุม ตัดช่องว่างหัวท้าย และยาวไม่เกิน `upload.name_max` ตัวอักษรโดยตัดส่วนชื่อแต่เก็บนามสกุล ชื่อที่ว่างหลังล้างใช้ `file` ตามด้วยนามสกุล ชื่อภาษาไทยคงไว้
- **เหตุผล:** ชื่อจากผู้ใช้อาจพาไปเขียนทับไฟล์อื่นหรือออกนอกโฟลเดอร์ ส่วนผู้ใช้ยังเห็นชื่อที่ตัวเองตั้ง
- **ถ้าผิด:** แก้ยาก — key ของไฟล์ที่เก็บไปแล้วต้องย้ายทั้งหมด
- **ถามเมื่อ:** ไม่ถาม

### UPL-D06: เก็บไฟล์ที่ไหน
- **คำตอบ:** object storage ที่ใช้ S3 API ได้ (MinIO ใน compose ของโปรเจกต์ หรือ bucket ของลูกค้า) bucket เป็นส่วนตัว ระหว่างพัฒนาและ test ใช้โฟลเดอร์ในเครื่อง ทุกแบบอยู่หลัง interface เดียว (เขียน อ่าน ลบ มีไหม) เลือกด้วย config ไม่แก้โค้ด เขียนทับ key เดิมไม่ได้ ไม่มีไฟล์ใดอยู่ใต้ web root หรือในฐานข้อมูล
- **เหตุผล:** รันหลาย instance ได้ สำรองแยกจากฐานข้อมูล และเปลี่ยนที่เก็บได้โดยโค้ดส่วนอื่นไม่รู้ตัว
- **ถ้าผิด:** แก้ทีหลังได้ — เปลี่ยนตัว implement แล้วย้ายไฟล์ด้วย script เพราะ key ไม่เปลี่ยน
- **ถามเมื่อ:** ทุกโปรเจกต์
- **ตัวเลือกอื่น:** b) volume หรือโฟลเดอร์บน server นอก web root (server เดียว ไม่มี object storage) c) ระบบเก็บเอกสารภายนอกของลูกค้าผ่าน API ของมัน d) เก็บในฐานข้อมูล (ไม่แนะนำ: ฐานข้อมูลโตและสำรองช้า)

### UPL-D07: ไฟล์ผูกกับรายการอย่างไร
- **คำตอบ:** ทะเบียนไฟล์กลาง `stored_file` หนึ่งแถวต่อไฟล์ และตารางผูกของแต่ละ `{record}` (`<record>_file`) ชี้มาที่ทะเบียน ทะเบียนไม่มีคอลัมน์ขอบเขต จึงห้าม query ทะเบียนตรงจากเส้นทางของผู้ใช้ ต้องเข้าผ่านตารางผูกของรายการเสมอ และมี architecture test ตรวจ
- **เหตุผล:** ตรวจชนิด เก็บ ล้าง และดาวน์โหลดเขียนครั้งเดียว ส่วนสิทธิ์และขอบเขตอยู่ที่รายการเจ้าของซึ่งมีอยู่แล้ว
- **ถ้าผิด:** แก้ยาก — ตารางและ FK ของไฟล์ทุกชนิดรายการ
- **ถามเมื่อ:** ไม่ถาม

### UPL-D08: ไฟล์เข้าระบบตอนไหน
- **คำตอบ:** อัปโหลดก่อน แล้วผูกตอนบันทึก: ไฟล์ขึ้นไปที่พัก `upload_staging` ทันทีที่เลือก ได้รหัสที่พักกลับมา ฟอร์มส่งรหัสที่พักไปกับการบันทึกของ `{record}` แล้วการบันทึกนั้นสร้างแถวทะเบียนและแถวผูก และลบแถวที่พักใน transaction เดียวกัน ไฟล์ไม่ถูกคัดลอก ไฟล์ในที่พักเป็นของผู้อัปโหลดคนเดียว ผูกได้ครั้งเดียว
- **เหตุผล:** ฟอร์มสร้างรายการใหม่แนบไฟล์ได้ก่อนรายการมีอยู่ ผู้ใช้เห็นข้อผิดพลาดของแต่ละไฟล์ทันที และยกเลิกฟอร์มแล้วไม่มีไฟล์ค้างบนรายการ
- **ถ้าผิด:** แก้ยาก — API ของทุกฟอร์มที่มีไฟล์และตารางที่พัก
- **ถามเมื่อ:** ไม่ถาม

### UPL-D09: ไฟล์ที่ค้างในที่พักทำอย่างไร
- **คำตอบ:** งานล้างรันทุกชั่วโมง ลบไฟล์และแถวที่พักที่อายุเกิน `upload.staging_hours` ชั่วโมงและยังไม่ถูกผูก ลบไฟล์ในที่เก็บที่ไม่มีแถวใดอ้างและเก่ากว่าค่าเดียวกัน ไม่ลง Activity Log และไม่แตะไฟล์ที่ผูกแล้ว ที่พักเป็นตารางชั่วคราวตาม AUDIT-D07
- **เหตุผล:** ฟอร์มที่ปิดทิ้งหรือ browser ที่ปิดไปไม่ทิ้งไฟล์ไว้ตลอดกาล
- **ถ้าผิด:** แก้ทีหลังได้ — ปรับอายุหรือรอบของงานล้าง
- **ถามเมื่อ:** ไม่ถาม

### UPL-D10: ดาวน์โหลดอย่างไร
- **คำตอบ:** ผ่าน API ของรายการเท่านั้น หลังตรวจว่าผู้ใช้ดู `{record}` นั้นได้ รายการนอกขอบเขต ไฟล์ที่เอาออกแล้ว และรหัสที่ไม่มีจริงตอบ 404 แบบเดียวกัน ตอบด้วย `Content-Disposition: attachment` และชื่อเดิม (มี `filename*` สำหรับชื่อภาษาไทย) `X-Content-Type-Options: nosniff` Content-Type เป็นชนิดที่ตรวจได้ และ `Cache-Control: private, no-store` ไม่มี URL ของที่เก็บไฟล์ออกไปถึงผู้ใช้
- **เหตุผล:** สิทธิ์ของไฟล์คือสิทธิ์ของรายการ 404 ไม่บอกว่ารายการมีอยู่ และ attachment กับ nosniff กันไฟล์ถูกเปิดเป็นหน้าเว็บของระบบ
- **ถ้าผิด:** แก้ยาก — เป็นเรื่องสิทธิ์และการรั่วของเอกสาร
- **ถามเมื่อ:** ไฟล์ใหญ่เกิน 100 MB หรือมีการดาวน์โหลดพร้อมกันจำนวนมากจน API รับไม่ไหว
- **ตัวเลือกอื่น:** b) หลังตรวจสิทธิ์ ให้ลิงก์ตรงไปที่เก็บไฟล์ที่หมดอายุใน 5 นาที (presigned URL) พร้อม header เดียวกัน

### UPL-D11: เปิดดูไฟล์บนจอหรือมีรูปย่อไหม
- **คำตอบ:** ไม่มี ทุกไฟล์ดาวน์โหลดอย่างเดียว ไม่มีรูปย่อและไม่เปิดในหน้าเว็บ
- **เหตุผล:** การเปิดไฟล์ในหน้าเว็บต้องมีกติกาความปลอดภัยเพิ่ม (CSP แยก domain) และงานสร้างรูปย่อ ซึ่งระบบส่วนใหญ่ไม่ต้องใช้
- **ถ้าผิด:** แก้ทีหลังได้ — เพิ่มการแสดงผลเป็น change แยก ข้อมูลที่เก็บไม่เปลี่ยน
- **ถามเมื่อ:** เอกสารลูกค้าขอดูไฟล์ในหน้าเว็บ รูปย่อ หรือรูปในเนื้อหา
- **ตัวเลือกอื่น:** b) เปิด PDF และรูปแบบ inline ในแท็บใหม่ พร้อม CSP sandbox c) สร้างรูปย่อของรูปภาพตอนผูก แสดงในรายการไฟล์

### UPL-D12: เอาไฟล์ออกหรือแทนที่อย่างไร
- **คำตอบ:** ตามกติกาของ `{record}`: คนที่แก้รายการได้ในสถานะที่แก้ได้ เอาออกในการบันทึกของรายการ เอาออกคือ soft delete ของแถวผูก (AUDIT-D05) แถวทะเบียนคงอยู่ แทนที่คือเอาออกแล้วแนบใหม่ในการบันทึกเดียว ไม่มีรายการรุ่นของไฟล์ ลบทั้งรายการแล้วแถวผูกไม่ถูกเอาออก
- **เหตุผล:** ไม่มีกติกาสิทธิ์ชุดที่สองสำหรับไฟล์ และประวัติยังบอกได้ว่าเคยมีไฟล์อะไร
- **ถ้าผิด:** แก้ทีหลังได้ — เพิ่มรายการรุ่นจากแถวผูกที่เอาออกแล้วได้
- **ถามเมื่อ:** เอกสารลูกค้าต้องการเก็บรุ่นของไฟล์และเปิดรุ่นเก่าได้
- **ตัวเลือกอื่น:** b) แทนที่แล้วรุ่นเก่ายังอยู่ในรายการรุ่นของไฟล์นั้น เปิดดูได้ตามสิทธิ์ของรายการ

### UPL-D13: เนื้อไฟล์ที่เอาออกแล้วเก็บนานแค่ไหน
- **คำตอบ:** เก็บ `upload.removed_retention_days` วันนับจากแถวผูกสุดท้ายที่ยังใช้ถูกเอาออก แล้วงานล้างรายวันลบเนื้อไฟล์ในที่เก็บ แถวทะเบียนคงอยู่พร้อม `purged_at` ไฟล์ของรายการที่ถูกลบทั้งรายการไม่ถูกล้าง งานล้างไม่ลง Activity Log
- **เหตุผล:** แก้การเอาออกผิดได้ระยะหนึ่ง แต่ไฟล์ที่ผู้ใช้ตั้งใจเอาออก (มักผิดไฟล์หรือมีข้อมูลส่วนบุคคล) ไม่ค้างตลอดไป
- **ถ้าผิด:** แก้ยาก — เนื้อไฟล์ที่ล้างไปแล้วเอาคืนไม่ได้
- **ถามเมื่อ:** เอกสารลูกค้ากำหนดอายุเก็บเอกสาร หรือต้องลบไฟล์ตามคำขอของเจ้าของข้อมูล
- **ตัวเลือกอื่น:** b) เก็บเนื้อไฟล์ตลอดไป c) ลบเนื้อไฟล์ทันทีที่เอาออก

### UPL-D14: เก็บ checksum ไหม และไฟล์ซ้ำทำอย่างไร
- **คำตอบ:** คำนวณ sha256 ระหว่างรับไฟล์ เก็บในที่พักและทะเบียน ไฟล์ที่ sha256 ตรงกับไฟล์ที่ยังผูกกับรายการเดียวกันยังรับได้ แต่คำตอบบอกไฟล์ที่ซ้ำ ให้จอเตือน ไม่ปฏิเสธ
- **เหตุผล:** ตรวจได้ว่าไฟล์ไม่เปลี่ยนตั้งแต่รับ และผู้ใช้รู้ตัวเมื่อแนบไฟล์เดิมซ้ำ โดยไม่ขวางกรณีที่ตั้งใจ
- **ถ้าผิด:** แก้ทีหลังได้ — คำนวณย้อนหลังจากไฟล์ที่ยังอยู่ได้
- **ถามเมื่อ:** ไม่ถาม

### UPL-D15: สแกนไวรัสไหม
- **คำตอบ:** ระบบที่มี `{org_portal}` หรือที่ลูกค้ากำหนด สแกนทุกไฟล์ระหว่างอัปโหลด ก่อนเก็บในที่พัก ด้วยตัวสแกนที่รันข้างระบบ (เช่น ClamAV) พบไวรัสก็ปฏิเสธ ตัวสแกนไม่ตอบใน `upload.scan_timeout_seconds` วินาทีก็ปฏิเสธพร้อมให้ลองใหม่ ไม่รับไฟล์ที่ยังไม่ได้สแกน ระบบที่มีแต่พนักงานอัปโหลดไม่สแกน
- **เหตุผล:** ไฟล์จากคนนอกเป็นทางเข้าหลักของมัลแวร์ ส่วนการสแกนตอนอัปโหลดทำให้ไม่มีสถานะ "รอสแกน" ค้างในระบบ
- **ถ้าผิด:** แก้ทีหลังได้ — เพิ่มตัวสแกนแล้วสแกนไฟล์ที่มีอยู่ย้อนหลังได้
- **ถามเมื่อ:** มี `{org_portal}` ที่อัปโหลดได้ แต่เอกสารลูกค้าไม่พูดถึงการสแกน (ต้องตกลงเครื่องและการดูแลตัวสแกน)
- **ตัวเลือกอื่น:** b) ไม่สแกน พึ่งการตรวจชนิดไฟล์และการดาวน์โหลดแบบ attachment c) ใช้บริการสแกนของที่เก็บไฟล์หรือ cloud ที่ลูกค้ามี

### UPL-D16: จำกัดจำนวนอัปโหลดต่อผู้ใช้ไหม
- **คำตอบ:** บน `{org_portal}` บัญชีหนึ่งอัปโหลดได้ไม่เกิน `upload.uploads_per_hour` ไฟล์ต่อชั่วโมง เกินแล้วตอบ 429 พร้อมเวลาที่ลองใหม่ได้ พอร์ทัลของพนักงานไม่จำกัดจำนวน มีแค่ขีดจำกัดขนาด
- **เหตุผล:** บัญชีคนนอกที่ถูกยึดหรือ script ผิดพลาดเติมพื้นที่เก็บไม่ได้ โดยไม่กระทบงานประจำของพนักงาน
- **ถ้าผิด:** แก้ทีหลังได้ — ปรับค่าหรือเพิ่มพอร์ทัลที่จำกัด
- **ถามเมื่อ:** ไม่ถาม

### UPL-D17: อะไรของไฟล์ลง Activity Log
- **คำตอบ:** อัปโหลดเข้าที่พัก ลบจากที่พัก และงานล้างไม่ลง การผูกและการเอาออกเป็นส่วนของการบันทึก `{record}` ในรายการเดียวกัน (AUDIT-D18) รายละเอียดมีชื่อไฟล์ ขนาด และ sha256 การบันทึกที่ทำแค่เรื่องไฟล์ใช้ชื่อการกระทำ `AttachFile` หรือ `RemoveFile` (AUDIT-D11)
- **เหตุผล:** ที่พักเป็นของชั่วคราว ลงไปก็มีแต่เสียง ส่วนไฟล์ที่ขึ้นหรือออกจากรายการคือการเปลี่ยนของรายการ
- **ถ้าผิด:** แก้ทีหลังได้ — log ใหม่ใช้กติกาใหม่ log เก่าคงเดิม
- **ถามเมื่อ:** ไม่ถาม

### UPL-D18: ลง log การดาวน์โหลดไหม
- **คำตอบ:** ไม่ลง
- **เหตุผล:** การดาวน์โหลดเกิดบ่อยและไม่เปลี่ยนข้อมูล ลงทุกครั้งทำให้ log บวมโดยระบบส่วนใหญ่ไม่ได้ใช้
- **ถ้าผิด:** แก้ยาก — การดาวน์โหลดที่ไม่ได้ลงไว้ย้อนหาไม่ได้
- **ถามเมื่อ:** ไฟล์เป็นเอกสารลับหรือมีข้อมูลส่วนบุคคลที่ต้องรู้ว่าใครเปิด หรือเอกสารลูกค้ากำหนด
- **ตัวเลือกอื่น:** b) ลง `Download` ทุกครั้ง พร้อมรายการและชื่อไฟล์ c) ลงเฉพาะ `{record}` ที่โปรเจกต์ระบุ

### UPL-D19: ผู้ใช้รู้ขีดจำกัดได้อย่างไร
- **คำตอบ:** API อ่านขีดจำกัดที่ใช้อยู่ (ชนิดที่รับ ขนาดต่อไฟล์ จำนวนและขนาดรวมต่อรายการ) ช่องแนบไฟล์แสดงค่านี้ ไม่เขียนค่าตายตัวในหน้าเว็บ หน้าเว็บตรวจก่อนส่งด้วยค่าเดียวกัน แต่ server ตรวจซ้ำเสมอ
- **เหตุผล:** ผู้ดูแลเปลี่ยนค่าแล้วจอตามทันที และผู้ใช้ไม่ต้องรออัปโหลดไฟล์ใหญ่จนจบแล้วค่อยรู้ว่าไม่รับ
- **ถ้าผิด:** แก้ทีหลังได้ — เป็นการแสดงผล
- **ถามเมื่อ:** ไม่ถาม
