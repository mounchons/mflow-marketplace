# MAIL: ข้อที่ตัดสินแล้ว

### MAIL-D01: อีเมลออกจากระบบอย่างไร
- **คำตอบ:** งานที่ทำให้เกิดอีเมลเขียนแถวลง `mail_outbox` ใน transaction เดียวกับงานนั้น แล้วตัวส่งแยกต่างหากหยิบไปส่งภายหลัง request ไม่เปิด SMTP เอง ยกเว้นปุ่มส่งทดสอบ (MAIL-D30)
- **เหตุผล:** งานที่ rollback ไม่ส่งอีเมล งานที่บันทึกแล้วไม่ทำอีเมลหาย และ SMTP ช้าหรือล่มไม่ทำให้หน้าจอค้าง
- **ถ้าผิด:** แก้ยาก — ทุกจุดที่ส่งอีเมลต้องเปลี่ยน และอีเมลที่ส่งไปแล้วเรียกคืนไม่ได้
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D02: ใครกำหนดว่าเหตุการณ์ไหนส่งอีเมล
- **คำตอบ:** เหตุการณ์ที่ส่งอีเมลกำหนดในโค้ด ผู้ใช้เปลี่ยนได้แค่เทมเพลตที่ผูกกับแต่ละแถวและสวิตช์ของแต่ละขั้น
- **เหตุผล:** แต่ละเหตุการณ์เติมแท็กได้ต่างกันและมีผู้รับต่างกัน การเพิ่มเหตุการณ์จากหน้าจอทำให้ส่งอีเมลที่ไม่มีค่าหรือผิดคน
- **ถ้าผิด:** แก้ทีหลังได้ — เพิ่มเหตุการณ์ใน change ถัดไป ไม่ต้องย้ายข้อมูล
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D03: เหตุการณ์ไหนส่งอีเมล และจัดเป็นขั้นอย่างไร
- **คำตอบ:** ใช้รายการเหตุการณ์จากเอกสารลูกค้า จัดเป็นขั้น (step) ตามจังหวะของงาน หนึ่งขั้นมีสวิตช์เดียวและมีได้หลายแถว แต่ละแถวผูกเทมเพลตเริ่มต้นหนึ่งฉบับ อีเมลบัญชีเป็นอีเมลตายตัวไม่อยู่ในขั้น
- **เหตุผล:** เหตุการณ์และถ้อยคำเป็นของธุรกิจแต่ละราย แพ็กให้แค่กลไก
- **ถ้าผิด:** แก้ยาก — อีเมลที่ส่งถึงลูกค้าและคู่ค้าผิดเรื่องหรือไม่ส่ง
- **ถามเมื่อ:** ทุกโปรเจกต์
- **ตัวเลือกอื่น:** b) ไม่มีจอผูก ทุกเหตุการณ์ส่งด้วยเทมเพลตของตัวเองเสมอ c) ทุกเหตุการณ์มีสวิตช์ของตัวเอง ไม่จัดเป็นขั้น

### MAIL-D04: อีเมลบัญชี (เชิญ ลิงก์ตั้งรหัส รหัสเข้าระบบ) ปิดได้ไหม
- **คำตอบ:** ไม่ได้ เป็นอีเมลตายตัว ส่งเสมอด้วยเทมเพลตระบบของตัวเอง (`account.invite`, `account.password_link`, `account.sign_in_code`) ไม่มีแถวบนจอผูก และปิดเทมเพลตไม่ได้ ผู้ดูแลรีเซ็ตรหัสให้ผู้ใช้ก็ใช้ `account.password_link`
- **เหตุผล:** ถ้าปิดได้ ผู้ใช้ใหม่เข้าระบบไม่ได้และลืมรหัสแล้วไม่มีทางกลับ
- **ถ้าผิด:** แก้ยาก — ผู้ใช้ถูกล็อกออกจากระบบโดยไม่มีใครรู้
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D05: ส่งจริงเมื่อไร
- **คำตอบ:** สวิตช์ `MAIL_SEND` ใน env ค่าเริ่มปิด ปิดอยู่อีเมลยังเข้าคิวและเห็นใน mailbox ของ prototype แต่ไม่เปิด SMTP เมื่อ start ด้วยสวิตช์เปิดครั้งแรก ระบบจำเวลานั้นเป็นจุดเริ่มส่ง และส่งเฉพาะอีเมลที่เข้าคิวตั้งแต่จุดนั้น start ด้วยสวิตช์ปิดล้างจุดเริ่มส่ง
- **เหตุผล:** เครื่องทดสอบใช้ระบบได้โดยไม่ส่งถึงคนจริง และเปิดสวิตช์แล้วอีเมลค้างเก่าไม่ไหลออกพร้อมกัน
- **ถ้าผิด:** แก้ยาก — อีเมลเก่าหลายร้อยฉบับถึงลูกค้าจริงพร้อมกัน
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D06: กันไม่ให้เครื่องทดสอบส่งถึงคนจริงอย่างไร
- **คำตอบ:** allow-list ผู้รับ เป็นค่าตั้งบนจอ ว่างคือส่งทุกคน มีค่าคือรับเฉพาะโดเมน (เขียนพร้อม `@`) และที่อยู่ที่ระบุ ไม่สนตัวพิมพ์ โดเมนต้องตรงหลัง `@` ผู้รับนอกรายการไม่ได้รับและลง log ทำให้รายการที่มีค่ากลายเป็นว่างต้องยืนยันก่อนบันทึก
- **เหตุผล:** เครื่องทดสอบเปิดส่งจริงได้โดยจำกัดผู้รับไว้ที่ทีม
- **ถ้าผิด:** แก้ยาก — อีเมลทดสอบถึงลูกค้าจริง
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D07: จำกัดจำนวนส่งไหม
- **คำตอบ:** ไม่เกิน `mail.max_per_hour` ข้อความในทุกช่วง 60 นาที หนึ่งผู้รับนับหนึ่งข้อความ เต็มแล้วอีเมลที่เหลือรอในคิวตามลำดับ ไม่ทิ้งและไม่ข้าม
- **เหตุผล:** mail server ภายในองค์กรมักจำกัดอัตราหรือมองว่าเป็น spam
- **ถ้าผิด:** แก้ทีหลังได้ — ปรับค่าบนจอ
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D08: รูปแบบของอีเมล
- **คำตอบ:** ข้อความล้วน UTF-8 ถึงผู้รับคนเดียวต่อข้อความ จากผู้ส่งเดียวของระบบ ไม่มีไฟล์แนบและไม่มีลิงก์ดาวน์โหลด ส่วนหัวและท้ายล็อกไว้นอกเนื้อความ
- **เหตุผล:** อ่านได้ทุกโปรแกรม ไม่หลุดข้อมูลทางไฟล์แนบ และผู้รับไม่เห็นที่อยู่ของกันและกัน
- **ถ้าผิด:** แก้ทีหลังได้ — เพิ่ม HTML ใน change ถัดไป เทมเพลตเดิมยังใช้ได้
- **ถามเมื่อ:** เอกสารลูกค้ากำหนดอีเมล HTML ตามแบรนด์ หรือต้องแนบไฟล์
- **ตัวเลือกอื่น:** b) HTML พร้อมข้อความล้วนสำรอง c) แนบไฟล์ได้ในบางเหตุการณ์

### MAIL-D09: mail server และที่อยู่ผู้ส่ง
- **คำตอบ:** ใช้ SMTP ของลูกค้า ค่า host, port, โหมด TLS, ผู้ใช้, รหัส, ลายนิ้วมือใบรับรอง, ที่อยู่และชื่อผู้ส่งอยู่บนหน้าตั้งค่าระบบ แก้ได้โดยไม่ restart รหัสเป็นค่าความลับของแพ็ก `settings` (เข้ารหัส ไม่ส่งกลับไปที่ browser) ทุกค่าไม่ลง log และไม่อยู่ในคำตอบ error
- **เหตุผล:** ทุกลูกค้ามี mail server และโดเมนของตัวเอง และผู้ดูแลแก้ค่าเองได้เมื่อ mail server เปลี่ยน โดยไม่ต้องรอคน deploy
- **ถ้าผิด:** แก้ทีหลังได้ — แก้บนหน้าตั้งค่า มีผลกับการส่งครั้งถัดไป
- **ถามเมื่อ:** ทุกโปรเจกต์
- **ตัวเลือกอื่น:** b) บริการส่งอีเมลภายนอกผ่าน API c) SMTP ของผู้ให้บริการภายนอก

### MAIL-D10: ต่อ SMTP แบบไหน
- **คำตอบ:** TLS เท่านั้น: STARTTLS (ค่าเริ่มต้น) หรือ TLS ตั้งแต่ไบต์แรก server ไม่เสนอ STARTTLS ถือว่าส่งไม่สำเร็จ ไม่ส่งแบบข้อความเปิด ตั้งลายนิ้วมือ SHA-256 ได้สำหรับใบรับรองที่ลงนามเอง ยืนยันตัวตนเมื่อมีทั้งผู้ใช้และรหัสเท่านั้น
- **เหตุผล:** อีเมลมีรหัสผ่านเริ่มต้นและลิงก์ตั้งรหัส และ server ในองค์กรมักใช้ใบรับรองที่ลงนามเอง
- **ถ้าผิด:** แก้ยาก — ความลับในอีเมลวิ่งบนเครือข่ายแบบเปิด
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D11: ส่งไม่สำเร็จแล้วทำอย่างไร
- **คำตอบ:** ลองใหม่ `mail.retry_minutes` ส่งเฉพาะผู้รับที่ยังไม่ได้ ครบ `mail.max_attempts` ครั้งเป็น Failed พร้อม error ล่าสุด ทุกครั้งที่พยายามเขียน `mail_log` หนึ่งแถว (ผล คำตอบ SMTP เนื้อความที่ปิดบังความลับ) `mail_log` แก้หรือลบไม่ได้ และไม่สร้าง Activity Log ต่อแถว
- **เหตุผล:** มีหลักฐานว่าส่งถึงใครเมื่อไร และ log ไม่ท่วม Activity Log
- **ถ้าผิด:** แก้ทีหลังได้ — เปลี่ยนรอบ retry ไม่ต้องย้ายข้อมูล
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D12: ถ้าตัวส่งสองรอบทำงานซ้อนกัน
- **คำตอบ:** ข้อความหนึ่งส่งได้ครั้งเดียว แม้สองรอบซ้อนกัน (ล็อกแถวหรือล็อกตัวส่ง)
- **เหตุผล:** ผู้รับไม่ควรได้รหัสหรือลิงก์ซ้ำ
- **ถ้าผิด:** แก้ทีหลังได้ — เพิ่มล็อกภายหลัง
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D13: หยิบอีเมลไหนก่อน
- **คำตอบ:** `account.sign_in_code` ก่อน แล้วเรียงตามเวลาเข้าคิว เก่าก่อน ตัวส่งดูคิวทุก `mail.poll_seconds` วินาที
- **เหตุผล:** ผู้ใช้ยืนรอรหัสอยู่หน้าจอ ส่วนอีเมลอื่นรอได้
- **ถ้าผิด:** แก้ทีหลังได้ — เปลี่ยนลำดับในโค้ด
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D14: ตัดสินว่าจะส่งตอนเข้าคิวหรือตอนหยิบ
- **คำตอบ:** ตอนหยิบ ตามตาราง: ก่อนจุดเริ่มส่งคงเป็น Queued, ความลับหมดอายุแล้ว Skipped, ไม่มีเทมเพลต Skipped, เทมเพลตปิด Skipped, ไม่มีผู้รับ Skipped, ไม่มีผู้รับใน allow-list Skipped, เต็มอัตราคงในคิว, นอกนั้นส่ง สถานะบัญชีอ่านตอนหยิบ และตัดสินใหม่ก่อนลองทุกครั้ง
- **เหตุผล:** บัญชีที่ถูกระงับระหว่างรอไม่ได้รับ และรหัสที่ใช้ไปแล้วไม่ถูกส่ง
- **ถ้าผิด:** แก้ทีหลังได้ — เพิ่มแถวในตารางตัดสิน
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D15: อีเมลถึง `{org}` ไปถึงใคร
- **คำตอบ:** ทุกบัญชีของ `{org}` ที่สถานะ Active หรือ Invited, `{org}` เองสถานะ Active และ role ของบัญชีเปิด `{area}` ของอีเมลนั้น แต่ละคนได้ข้อความของตัวเอง อีเมลถึงบัญชีเดียวไปที่อีเมลของบัญชีนั้น บัญชีที่ลบแล้วหรือไม่มีอีเมลไม่มีผู้รับ
- **เหตุผล:** คนที่ยังไม่เคยเข้าระบบก็ควรรู้ว่ามีงานรอ และคนที่ไม่ได้ดูแลเรื่องนั้นไม่ได้รับ
- **ถ้าผิด:** แก้ยาก — อีเมลถึงคนที่ไม่ควรเห็นข้อมูล หรือคนที่ต้องทำงานไม่รู้
- **ถามเมื่อ:** ระบบส่งอีเมลถึงหน่วยที่มีหลายบัญชี
- **ตัวเลือกอื่น:** b) ส่งถึงบัญชีหลักของ `{org}` บัญชีเดียว c) ส่งถึงทุกบัญชีที่ Active ไม่ดู role

### MAIL-D16: ความลับในอีเมลเก็บอย่างไร
- **คำตอบ:** รหัสผ่านเริ่มต้น โทเค็นลิงก์ และรหัสเข้าระบบ ไม่อยู่ในค่าของอีเมล เก็บเข้ารหัสด้วยกุญแจ `MAIL_SECRET_KEY` คู่กับแถวในคิว ล้างเมื่อส่งแล้ว เมื่อครบ `mail.secret_hours` ชั่วโมง หรือเมื่อรหัสใช้ไม่ได้แล้ว ใน `mail_log` ปิดบังเสมอ
- **เหตุผล:** ฐานข้อมูลหรือ log หลุดแล้วไม่มีรหัสที่ยังใช้ได้
- **ถ้าผิด:** แก้ยาก — ต้องยกเลิกรหัสและลิงก์ที่ออกไปแล้วทั้งหมด
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D17: ผู้ใช้สร้างหรือลบเทมเพลตได้ไหม
- **คำตอบ:** เทมเพลตระบบมี key และชื่อตายตัว ลบไม่ได้ ผู้ใช้สร้างเทมเพลตใหม่ได้ด้วยการคัดลอกเท่านั้น สำเนาต้องมีชื่ออังกฤษและไทยไม่ซ้ำ และลบได้ (soft delete) เมื่อไม่มีแถวใดผูกอยู่
- **เหตุผล:** ได้ถ้อยคำเฉพาะกรณีโดยไม่เสียเทมเพลตตั้งต้น และอีเมลเก่ายังแสดงชื่อเทมเพลตได้
- **ถ้าผิด:** แก้ทีหลังได้ — เปิดหรือปิดการคัดลอกได้โดยไม่ย้ายข้อมูล
- **ถามเมื่อ:** เอกสารลูกค้ากำหนดว่าทะเบียนเทมเพลตเป็นชุดปิด
- **ตัวเลือกอื่น:** b) ชุดปิด แก้ได้แค่หัวเรื่องและเนื้อความ c) สร้างเทมเพลตเปล่าได้ด้วย

### MAIL-D18: แท็กในเทมเพลต
- **คำตอบ:** รายการแท็กกำหนดในโค้ด บันทึกเทมเพลตที่มีแท็กอื่นถูกปฏิเสธพร้อมชื่อแท็ก แท็กที่ไม่มีค่าแสดงเป็นว่าง ไม่มีวงเล็บปีกกาถึงผู้รับ แต่ละเหตุการณ์มีรายการแท็กที่เติมได้ จอผูกเตือน (ไม่ห้าม) เมื่อเทมเพลตใช้แท็กที่เหตุการณ์ของแถวเติมไม่ได้
- **เหตุผล:** พิมพ์แท็กผิดถูกจับตอนบันทึก และการผูกข้ามเหตุการณ์ยังทำได้เมื่อตั้งใจ
- **ถ้าผิด:** แก้ทีหลังได้ — เพิ่มแท็กในโค้ด
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D19: แท็กบังคับของอีเมลบัญชี
- **คำตอบ:** `account.invite` ต้องมี `{{temp_password}}` และ `{{confirm_link}}`, `account.password_link` ต้องมี `{{reset_link}}`, `account.sign_in_code` ต้องมี `{{code}}` บันทึกโดยไม่มีถูกปฏิเสธ สำเนาของสามฉบับนี้ไม่บังคับ เพราะผูกกับอีเมลตายตัวไม่ได้ รหัสอยู่ในเนื้อความ ไม่อยู่ในหัวเรื่อง
- **เหตุผล:** ถ้าลบแท็กพลาด ผู้ใช้ได้อีเมลที่ใช้ทำอะไรไม่ได้
- **ถ้าผิด:** แก้ยาก — ผู้ใช้ได้อีเมลเชิญหรือรีเซ็ตที่ไม่มีลิงก์
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D20: อีเมลภาษาอะไร
- **คำตอบ:** หัวเรื่องหนึ่งและเนื้อความหนึ่งใช้ร่วมทั้งสองภาษา (ไทยและอังกฤษในฉบับเดียว) ชื่อเทมเพลตมีทั้งอังกฤษและไทย วันที่แสดงตาม `mail.date_format`
- **เหตุผล:** ไม่ต้องรู้ภาษาของผู้รับ และดูแลข้อความชุดเดียว
- **ถ้าผิด:** แก้ทีหลังได้ — แยกเนื้อความตามภาษาเพิ่มคอลัมน์ได้
- **ถามเมื่อ:** ทุกโปรเจกต์
- **ตัวเลือกอื่น:** b) แยกเนื้อความต่อภาษา ส่งตามภาษาของบัญชี c) ภาษาไทยอย่างเดียว

### MAIL-D21: ปิดเทมเพลตแล้วเกิดอะไร
- **คำตอบ:** เทมเพลตที่ปิดไม่ถูกส่ง ไม่อยู่ในรายการให้เลือก และผูกไม่ได้ ปิดเทมเพลตที่ผูกอยู่ต้องยืนยันโดยระบุทุกแถวที่ผูก แล้วแถวเหล่านั้นไม่มีเทมเพลตใน transaction เดียวกัน เปิดใหม่ไม่ผูกกลับ
- **เหตุผล:** ไม่มีแถวใดผูกกับเทมเพลตที่ปิด และผู้ใช้เห็นผลก่อนกด
- **ถ้าผิด:** แก้ทีหลังได้ — เปลี่ยนพฤติกรรมในโค้ด
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D22: จอผูกเหตุการณ์กับเทมเพลต
- **คำตอบ:** แสดงทุกขั้น แต่ละขั้นมีสวิตช์และแถว แต่ละแถวเลือกเทมเพลตที่เปิดอยู่ บันทึกทุกขั้นทุกแถวพร้อมกันใน transaction เดียวหลังยืนยันที่แสดงทุกคู่ ขั้นที่เปิดต้องมีเทมเพลตทุกแถว มีปุ่มคืนค่าเริ่มต้นที่ยืนยันโดยแสดงแต่ละการเปลี่ยน
- **เหตุผล:** เห็นภาพทั้งระบบในหน้าเดียว และไม่มีขั้นที่เปิดอยู่แต่ส่งไม่ได้
- **ถ้าผิด:** แก้ทีหลังได้ — ปรับหน้าจอ ข้อมูลเดิมใช้ต่อ
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D23: สวิตช์และการผูกมีผลตอนไหน
- **คำตอบ:** ตอนเข้าคิว: ขั้นปิดไม่เข้าคิวเลย (ไม่มี log), ขั้นเปิดเข้าคิวพร้อมเทมเพลตที่ผูกขณะนั้น, แถวไม่มีเทมเพลตเข้าคิวโดยไม่มีเทมเพลต อีเมลในคิวคงเทมเพลตเดิมแม้เปลี่ยนการผูกภายหลัง อีเมลตายตัวใช้เทมเพลตระบบของตัวเองเสมอ
- **เหตุผล:** เปิดขั้นทีหลังไม่ส่งเรื่องเก่าย้อนหลัง
- **ถ้าผิด:** แก้ทีหลังได้ — เปลี่ยนจุดตัดสินในโค้ด
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D24: ผู้ทดสอบเห็นอีเมลอย่างไรเมื่อยังไม่มี SMTP
- **คำตอบ:** หน้า mailbox ของ prototype บนแต่ละ `{portal}` เปิดได้โดยไม่ต้องเข้าระบบ แสดงอีเมลในคิวถึงบัญชีของ `{portal}` นั้น ใหม่ก่อน พร้อมเนื้อความและความลับที่ยังไม่ถูกล้าง มีเฉพาะเมื่อโหมด prototype เปิด ปิดโหมดแล้ว API ไม่ให้บริการ
- **เหตุผล:** ทดสอบเชิญ ลืมรหัส และ OTP ได้ครบโดยไม่ต้องมี mail server
- **ถ้าผิด:** แก้ยาก — ถ้าหลุดไปเปิดบน production ทุกคนเห็นรหัสของทุกบัญชี
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D25: ค่าไหนตั้งบนจอ ค่าไหนอยู่ใน env
- **คำตอบ:** อัตราต่อชั่วโมง allow-list ชื่อบริษัท และค่า SMTP ทั้งชุด (MAIL-D09) อยู่ในหน้าตั้งค่าระบบ มีผลรอบส่งถัดไปโดยไม่ restart ค่า env เดิมของค่าเหล่านี้ใช้เป็นค่าตั้งต้นครั้งแรกเท่านั้น สวิตช์ส่ง `MAIL_SEND` กุญแจความลับ `MAIL_SECRET_KEY` และ URL ของแต่ละ `{portal}` คงอยู่ใน env
- **เหตุผล:** ค่าที่ปรับระหว่างใช้งานไม่ต้อง deploy ส่วนสวิตช์ส่งอยู่กับ environment เพื่อให้ฐานข้อมูลที่คัดลอกจาก production ไปเครื่องทดสอบไม่ส่งอีเมลถึงคนจริง
- **ถ้าผิด:** แก้ทีหลังได้ — ย้ายค่าระหว่าง env กับจอได้
- **ถามเมื่อ:** ไม่ถาม
- **ตัวเลือกอื่น:** b) ทุกค่าอยู่ใน env เปลี่ยนแล้ว restart

### MAIL-D26: ตรวจค่าอะไรตอน start
- **คำตอบ:** สวิตช์ส่งเปิดอยู่ ขาด URL ของทุก `{portal}` หรือ `MAIL_SECRET_KEY` แล้ว API ไม่ start ค่าที่อ่านไม่ได้ทำให้ไม่ start เช่นกัน ข้อความระบุชื่อค่าแต่ไม่แสดงค่า สวิตช์ปิดไม่ต้องมีค่าเหล่านี้ ค่า SMTP บนจอยังไม่ครบ (host หรือที่อยู่ผู้ส่ง) API ยัง start ได้ ตัวส่งคงอีเมลไว้ใน Queued โดยไม่นับเป็นการลอง และหน้าตั้งค่ากับ health แสดงว่า SMTP ยังไม่ได้ตั้ง
- **เหตุผล:** รู้ตั้งแต่ deploy ไม่ใช่ตอนลูกค้าบอกว่าไม่ได้อีเมล ส่วนค่าบนจอตั้งได้หลังระบบขึ้นแล้วโดยไม่มีอีเมลหาย
- **ถ้าผิด:** แก้ทีหลังได้ — เพิ่มการตรวจได้
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D27: เทมเพลตระบบลงฐานข้อมูลอย่างไร
- **คำตอบ:** ใส่ตอน start เฉพาะที่ยังไม่มี ไม่ทับข้อความที่ผู้ใช้แก้ ชื่อของเทมเพลตระบบปรับตามโค้ดทุกครั้ง ข้อความตั้งต้นเป็นฉบับชั่วคราวจนลูกค้าส่งฉบับจริง และต้องผ่านกฎแท็กของแพ็กนี้
- **เหตุผล:** อัปเดตระบบแล้วงานแก้ข้อความของลูกค้าไม่หาย
- **ถ้าผิด:** แก้ทีหลังได้ — เปลี่ยน seed ได้
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D28: สองคนแก้พร้อมกัน
- **คำตอบ:** บันทึกเทมเพลตและการผูกส่ง version ที่อ่านมา version เก่ากว่าตอบ 409 และไม่เปลี่ยนอะไร การบันทึกการผูก การคืนค่าเริ่มต้น การปิดเทมเพลต และการลบสำเนา ทำทีละรายการ
- **เหตุผล:** ไม่มีใครทับงานของอีกคนโดยไม่รู้ และไม่มีแถวผูกกับเทมเพลตที่ปิด
- **ถ้าผิด:** แก้ทีหลังได้ — เพิ่ม version ในตารางได้
- **ถามเมื่อ:** ไม่ถาม

### MAIL-D30: ทดสอบค่า SMTP อย่างไร
- **คำตอบ:** แท็บอีเมลมีปุ่มส่งทดสอบ ส่งข้อความสั้นหนึ่งฉบับด้วยค่าที่บันทึกแล้วไปยังที่อยู่ที่พิมพ์ (ค่าเริ่มเป็นอีเมลของผู้กด) ทันทีในคำขอนั้น ไม่ผ่านคิว รอไม่เกิน 30 วินาที แล้วแสดงผลพร้อมคำตอบของ SMTP ที่ไม่มีค่าตั้งใดๆ ผู้รับต้องผ่าน allow-list สวิตช์ส่งปิดอยู่ตอบว่าส่งไม่ได้เพราะ env ไม่เปิดให้ส่ง ทุกครั้งลง `mail_log` และ Activity Log
- **เหตุผล:** ผู้ดูแลรู้ทันทีว่าค่าที่เพิ่งแก้ใช้ได้ ไม่ต้องรอให้ผู้ใช้บอกว่าไม่ได้อีเมล
- **ถ้าผิด:** แก้ทีหลังได้ — เป็นปุ่มเดียวที่ไม่กระทบคิว
- **ถามเมื่อ:** ไม่ถาม
