# import-export: ข้อที่ตอบไว้แล้ว

### IMPEX-D01: ใครนำเข้าได้ และเห็นชุดนำเข้าของใคร
- **คำตอบ:** แต่ละ `{import_target}` มีคำสั่งเดียว `{import_key}` ครอบการอัปโหลด ดูผลตรวจ ดาวน์โหลดรายงาน ยืนยัน และยกเลิก แยกจากสิทธิ์แก้รายการทีละแถว seed ให้กลุ่มผู้ดูแลสูงสุดเท่านั้น ชุดนำเข้าเป็นของคนอัปโหลดคนเดียว คนอื่นขอได้ 404 แถวที่ชี้รายการนอกขอบเขตข้อมูลของคนนำเข้าเป็นแถวผิด และการตรวจว่ารหัสนั้นมีอยู่ไม่อ่านฟิลด์อื่นของรายการ
- **เหตุผล:** การนำเข้าเปลี่ยนข้อมูลได้ทีละหลายพันแถว จึงไม่ควรติดมากับสิทธิ์แก้ทั่วไป และไฟล์ของคนหนึ่งมีข้อมูลที่อีกคนอาจไม่ควรเห็น
- **ถ้าผิด:** แก้ยาก — แถวนอกขอบเขตที่ผ่านเข้าไปคือข้อมูลรั่วและถูกเขียนทับข้ามขอบเขต
- **ถามเมื่อ:** ทุกโปรเจกต์
- **ตัวเลือกอื่น:** b) ใช้สิทธิ์เดียวกับการแก้ `{import_target}` ไม่มีคำสั่งแยก c) ให้กลุ่มหัวหน้างานถือ `{import_key}` ตั้งแต่ seed

### IMPEX-D02: รับไฟล์ชนิดไหน และไฟล์ขึ้นมาทางไหน
- **คำตอบ:** `.xlsx` เท่านั้น หนึ่งไฟล์ต่อคำขอ ที่ endpoint ของการนำเข้าเอง ไม่ขึ้นกับรายการ `upload.extensions` ส่วนการตรวจเนื้อไฟล์ การล้างชื่อ และที่เก็บไฟล์ใช้โค้ดเดียวกับแพ็ก upload (UPL-D04, UPL-D05, UPL-D06) `.xls` `.csv` `.xlsm` ถูกปฏิเสธพร้อมข้อความให้บันทึกเป็น `.xlsx` จากแม่แบบ
- **เหตุผล:** ผู้ดูแลติ๊ก `.xlsx` ออกจากชนิดไฟล์แนบแล้วการนำเข้าต้องยังทำงาน และไฟล์นำเข้าไม่ใช่ไฟล์แนบของรายการ แต่การตรวจไฟล์ปลอมต้องเป็นชุดเดียวกัน
- **ถ้าผิด:** แก้ทีหลังได้ — เพิ่มตัวอ่านของชนิดอื่นหลัง interface เดียวกัน
- **ถามเมื่อ:** ระบบต้นทางส่งออกได้เฉพาะ `.csv` หรือ `.xls` หรือผู้ใช้มีไฟล์รุ่นเก่าจำนวนมาก
- **ตัวเลือกอื่น:** b) รับ `.csv` (UTF-8 พร้อม BOM) เพิ่ม ตรวจด้วยกติกาเดียวกัน c) รับ `.xls` เพิ่มด้วย library อ่านไฟล์รุ่นเก่า

### IMPEX-D03: ไฟล์ใหญ่ได้แค่ไหน
- **คำตอบ:** ไฟล์ไม่เกิน `import-export.import_max_file_mb` MB ไม่เกิน `import-export.import_max_rows` แถวใต้หัวตาราง ทุกชีทไม่เกิน `import-export.import_max_columns` คอลัมน์ ไม่เกิน `import-export.import_max_sheets` ชีท เซลล์ละไม่เกิน `import-export.import_max_cell_chars` ตัวอักษร และแตกแล้วรวมไม่เกิน `import-export.import_max_unpacked_mb` MB ตรวจขนาดแตกไฟล์ก่อนอ่านเซลล์แรก ไม่ผ่านข้อใดปฏิเสธทั้งไฟล์พร้อมบอกค่าที่เกิน
- **เหตุผล:** `.xlsx` เป็น zip ไฟล์ไม่กี่ KB แตกออกมาได้เป็น GB และตัวอ่านส่วนใหญ่โหลดทั้งไฟล์เข้าหน่วยความจำ จึงต้องหยุดก่อนอ่าน
- **ถ้าผิด:** แก้ทีหลังได้ — ปรับค่าได้ ค่าที่ตั้งบนจอไม่ต้อง deploy
- **ถามเมื่อ:** ไฟล์จริงของลูกค้าเกินค่าเริ่มต้น
- **ตัวเลือกอื่น:** b) เพิ่มขีดจำกัดตามไฟล์จริง และเปลี่ยนตัวอ่านเป็นแบบ stream c) ให้ผู้ใช้แบ่งไฟล์

### IMPEX-D04: แม่แบบมาจากไหน
- **คำตอบ:** หน้านำเข้ามีปุ่มดาวน์โหลดแม่แบบ ระบบสร้างตอนกดจากนิยามคอลัมน์ชุดเดียวกับที่ตัวอ่านใช้ (ชื่อหัว ลำดับ บังคับกรอก ชนิด ความยาว ค่าที่รับ ตัวอย่าง) ชีทแรกมีแถวหัวแถวเดียว คอลัมน์บังคับกรอกต่อท้ายชื่อด้วย ` *` คอลัมน์รหัสตั้งรูปแบบเซลล์เป็น Text ชีทที่สองชื่อ `คำอธิบาย` บอกกติกาทีละคอลัมน์ และตัวอ่านข้ามชีทนี้ ไม่มีแถวตัวอย่างในชีทข้อมูล
- **เหตุผล:** แม่แบบกับตัวอ่านไม่มีทางไม่ตรงกัน และแถวตัวอย่างในชีทข้อมูลมีโอกาสถูกนำเข้าจริง
- **ถ้าผิด:** แก้ทีหลังได้ — แม่แบบสร้างใหม่ทุกครั้งที่กด
- **ถามเมื่อ:** เอกสารลูกค้ามีไฟล์แม่แบบของตัวเอง หรือไฟล์มาจากระบบต้นทางที่กำหนดหัวคอลัมน์มาแล้ว
- **ตัวเลือกอื่น:** b) ใช้ชื่อหัวและลำดับตามไฟล์ของลูกค้าในนิยามคอลัมน์ แม่แบบยังสร้างจากนิยามเดียวกัน c) ใส่แถวตัวอย่างหนึ่งแถวในชีทข้อมูล และตัวอ่านข้ามแถวที่มีเครื่องหมายตัวอย่าง

### IMPEX-D05: อ่านชีทและคอลัมน์อย่างไร
- **คำตอบ:** หาจากหัวตารางในแถวที่ 1 ไม่ดูชื่อชีทหรือลำดับชีท ชีทข้อมูลคือชีทที่มีคอลัมน์บังคับกรอกครบ นับชีทที่ซ่อนด้วย ไม่พบหรือพบสองชีทปฏิเสธทั้งไฟล์ หัวคอลัมน์เทียบแบบไม่สนตัวพิมพ์ ช่องว่างหัวท้าย ` *` ต่อท้าย และ `_` กับช่องว่าง เรียงลำดับไหนก็ได้ ขาดคอลัมน์บังคับกรอก หัวซ้ำ หรือมีคอลัมน์ที่นิยามไม่รู้จักปฏิเสธทั้งไฟล์พร้อมบอกชื่อชีทและคอลัมน์ คอลัมน์หัวว่างและแถวว่างข้าม แถวและคอลัมน์ที่ซ่อนอ่านตามปกติ
- **เหตุผล:** ผู้ใช้เปลี่ยนชื่อชีทและลำดับคอลัมน์ได้เป็นปกติ ส่วนคอลัมน์แปลกมักแปลว่าใช้ไฟล์ผิด จึงควรหยุดก่อนอ่านข้อมูลผิดเข้าไป
- **ถ้าผิด:** แก้ทีหลังได้ — เปลี่ยนกติกาโครงไฟล์ได้โดยไม่แตะข้อมูลที่บันทึกแล้ว
- **ถามเมื่อ:** ไฟล์มาจากระบบต้นทางที่เพิ่มคอลัมน์เองได้
- **ตัวเลือกอื่น:** b) ข้ามคอลัมน์ที่ไม่รู้จัก และบอกชื่อคอลัมน์ที่ข้ามบนหน้าผลตรวจ c) อ่านตามชื่อชีทที่นิยามระบุ

### IMPEX-D06: ตรวจเมื่อไร และผลตรวจแสดงอย่างไร
- **คำตอบ:** ตรวจทั้งไฟล์ก่อนบันทึกข้อมูลธุรกิจ ค่าที่อ่านได้ทุกแถวเก็บในตารางชั่วคราว `import_row` พร้อมข้อผิดของแถวนั้น ไม่หยุดที่แถวแรก (AUDIT-D07) หน้าผลตรวจแสดงจำนวนแถวที่ผ่าน ไม่ผ่าน จะสร้าง จะแก้ และรายการแถวผิดพร้อมเลขแถว คอลัมน์ เหตุผล เลขแถวคือเลขแถวของ Excel หัวตารางเป็นแถว 1 แถวที่ถูกข้ามไม่ทำให้เลขเลื่อน ไม่มีแถวข้อมูลเลยไปต่อไม่ได้
- **เหตุผล:** ผู้ใช้แก้ไฟล์ครั้งเดียวได้ครบทุกแถว ไม่ต้องอัปโหลดวนทีละข้อผิด และไม่มีข้อมูลธุรกิจเปลี่ยนก่อนยืนยัน
- **ถ้าผิด:** แก้ยาก — ตารางชั่วคราว API และหน้าผลตรวจเปลี่ยนทั้งหมด
- **ถามเมื่อ:** ไม่ถาม

### IMPEX-D07: ไฟล์ที่มีแถวผิดบันทึกอย่างไร
- **คำตอบ:** เตือนก่อนเสมอ: หน้าผลตรวจบอกจำนวนแถวที่ผ่านและไม่ผ่าน ผู้ใช้ดูแถวที่มีปัญหาพร้อมเลขแถว คอลัมน์ และเหตุผล และดาวน์โหลดรายงานได้ ถ้ายืนยัน นำเข้าเฉพาะแถวที่ผ่าน แถวที่ไม่ผ่านไม่ถูกบันทึกและอยู่ในรายงาน ถ้ายกเลิก ไม่มีอะไรถูกบันทึก ถ้ารายการหนึ่งมีหลายแถว แถวหนึ่งผิดรายการนั้นไม่ผ่านทั้งรายการ ไม่มีแถวที่ผ่านเลยยืนยันไม่ได้ ไฟล์ที่ผิดทั้งไฟล์ (หัวตารางผิด เกินขีดจำกัด) ถูกปฏิเสธก่อนถึงขั้นนี้
- **เหตุผล:** ผู้ใช้เห็นผลและตัดสินเองก่อนบันทึก และไม่ต้องแก้ทั้งไฟล์เพียงเพราะแถวผิดไม่กี่แถว
- **ถ้าผิด:** แก้ทีหลังได้ — ใช้ผลตรวจเดิม ไม่เปลี่ยนตาราง
- **ถามเมื่อ:** ข้อมูลในไฟล์ต้องครบชุดจึงใช้ได้ เช่น ยอดต้องลงตัวทั้งไฟล์
- **ตัวเลือกอื่น:** b) ทั้งไฟล์หรือไม่มีเลย: มีแถวผิดแม้แถวเดียวยืนยันไม่ได้ ผู้ใช้แก้ในไฟล์แล้วอัปโหลดใหม่

### IMPEX-D08: รายงานข้อผิดพลาดเป็นอย่างไร
- **คำตอบ:** ดาวน์โหลดเป็น `.csv` UTF-8 พร้อม BOM ให้ Excel แสดงภาษาไทยได้ มีครบทุกข้อผิดของไฟล์ ไม่ใช่แค่หน้าที่เห็น คอลัมน์ Row, Sheet, Column, Reason ค่าที่ขึ้นต้นด้วยอักขระสูตรถูกกันตาม IMPEX-D22
- **เหตุผล:** ผู้ใช้แก้ไฟล์ทีละแถวตามรายงานได้โดยไม่ต้องเปิดจอค้างไว้ และ CSV เปิดได้ทุกเครื่อง
- **ถ้าผิด:** แก้ทีหลังได้ — เพิ่มรูปแบบรายงานจากผลตรวจเดิมได้
- **ถามเมื่อ:** ผู้ใช้ต้องแก้แถวผิดแล้วส่งซ้ำเป็นงานประจำ
- **ตัวเลือกอื่น:** b) ไฟล์ `.xlsx` ตามแม่แบบ มีเฉพาะแถวผิดพร้อมคอลัมน์เหตุผลต่อท้าย แก้แล้วอัปโหลดซ้ำได้ (ตัวอ่านข้ามคอลัมน์เหตุผล)

### IMPEX-D09: จับคู่รายการเดิมอย่างไร และแถวซ้ำในไฟล์ทำอย่างไร
- **คำตอบ:** จับคู่ด้วย `{match_key}` ที่นิยามของ `{import_target}` กำหนด เทียบแบบไม่สนตัวพิมพ์และช่องว่างหัวท้าย ไม่นับรายการที่ลบแล้ว (AUDIT-D06) ไม่พบคือสร้าง พบคือแก้ `{match_key}` ซ้ำกันในไฟล์เป็นแถวผิดทุกแถวที่ซ้ำ ระบบไม่เลือกแถวให้ และการนำเข้าไม่ลบรายการ
- **เหตุผล:** ไฟล์เดียวกันส่งซ้ำได้ผลเดิม และระบบไม่ควรเดาว่าแถวไหนในสองแถวที่ขัดกันคือแถวที่ถูก
- **ถ้าผิด:** แก้ยาก — เลือกคีย์ผิดแล้วสร้างรายการซ้ำหรือเขียนทับรายการผิดจำนวนมาก
- **ถามเมื่อ:** ทุกโปรเจกต์
- **ตัวเลือกอื่น:** b) สร้างอย่างเดียว พบรายการเดิมเป็นแถวผิด c) แก้อย่างเดียว ไม่พบเป็นแถวผิด d) แถวซ้ำในไฟล์ใช้แถวล่างสุด พร้อมบอกจำนวนบนหน้าผลตรวจ

### IMPEX-D10: การแก้รายการเดิมเขียนทับอะไรได้
- **คำตอบ:** เขียนทับเฉพาะคอลัมน์ที่นิยามกำกับว่าแก้จากไฟล์ได้ ช่องว่างในไฟล์ไม่เปลี่ยนค่าเดิม ล้างค่าทำบนจอ สถานะงาน รหัสภายใน และคอลัมน์ผู้ทำไม่อยู่ในไฟล์เสมอ รายการที่สถานะห้ามแก้เป็นแถวผิด รายการที่ไม่อยู่ในไฟล์ไม่ถูกแตะ
- **เหตุผล:** ไฟล์ที่ขาดข้อมูลบางช่องไม่ควรลบของเดิม และคนนำเข้าไม่ควรเปลี่ยนสถานะงานผ่านไฟล์
- **ถ้าผิด:** แก้ยาก — ค่าที่ไฟล์ผิดเขียนทับไปแล้วเอาคืนได้จาก Activity Log ทีละฟิลด์เท่านั้น
- **ถามเมื่อ:** ระบบต้นทางเป็นเจ้าของข้อมูลและไฟล์คือค่าล่าสุดทั้งหมด
- **ตัวเลือกอื่น:** b) ช่องว่างล้างค่าเดิม ไฟล์คือความจริงทั้งหมด c) ช่องว่างไม่เปลี่ยน แต่มีคำพิเศษเช่น `-` สำหรับล้างค่า

### IMPEX-D11: อ่านวันที่อย่างไร
- **คำตอบ:** อ่านค่าที่เซลล์เก็บจริง เซลล์วันที่เป็นวันตามปฏิทิน ไม่ขึ้นกับรูปแบบที่แสดงหรือภาษาของเครื่อง เซลล์ข้อความรับรูป `import-export.date_text_format` ปีสี่หลักเท่านั้น ปีตั้งแต่ `import-export.buddhist_year_from` ขึ้นไปถือเป็น พ.ศ. และลบ 543 ก่อนตรวจว่าเป็นวันที่จริง ทั้งเซลล์ข้อความและเซลล์วันที่ที่คนพิมพ์ พ.ศ. ลง Excel แบบ ค.ศ. ตัวเลขเปล่าในคอลัมน์วันที่ วันที่ไม่มีจริง และปีสองหลักเป็นแถวผิด ไฟล์ที่ใช้ระบบวันที่ 1904 ถูกปฏิเสธทั้งไฟล์
- **เหตุผล:** Excel เก็บวันที่เป็นเลขลำดับวัน คนไทยพิมพ์ปีได้ทั้งสองแบบ และเลขเปล่าเดาไม่ได้ว่าเป็นวันที่หรือจำนวน
