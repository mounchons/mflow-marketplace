# ข้อตัดสินใจของแพ็ก settings

### SET-D01: ค่าบนหน้าตั้งค่ามาจากไหน
- **คำตอบ:** catalog ในโค้ดรายการเดียว รวมทุกคีย์ใน params.md ของแพ็กที่โปรเจกต์เลือก (ยกเว้นตาม SET-D02) และคีย์ของโปรเจกต์เอง แต่ละคีย์มีแท็บ ชนิด หน่วย ช่วง ค่าเริ่มต้น ชื่อ และคำอธิบาย แท็บละหนึ่งแพ็ก หรือหลายแท็บเมื่อแพ็กเจ้าของกำกับ `แท็บ <ชื่อ>` เรียงตามลำดับแพ็กแล้วตามด้วยแท็บของโปรเจกต์ ในแท็บเรียงตามแถวของ params.md ฐานข้อมูลเก็บแค่ค่า catalog เปลี่ยนพร้อมโค้ดเท่านั้น
- **เหตุผล:** แพ็กเจ้าของรู้ดีที่สุดว่าค่าคืออะไรและรับช่วงไหน หน้าตั้งค่าแค่แสดงและบันทึกตามกติกาเดียว เลือกแพ็กเพิ่มแล้วค่าของมันขึ้นจอเองโดยไม่ต้องออกแบบหน้าใหม่
- **ถ้าผิด:** แก้ทีหลังได้ — ย้ายคีย์ระหว่างแท็บหรือเปลี่ยนลำดับเป็นแค่การแก้ catalog
- **ถามเมื่อ:** ไม่ถาม

### SET-D02: คีย์ไหนไม่ขึ้นจอ
- **คำตอบ:** คีย์ที่แพ็กเจ้าของกำกับ `ไม่ขึ้นจอ` คีย์ที่ไม่ได้กำกับ `ตั้งบนจอ` ในแพ็กที่บอกว่าเฉพาะค่าที่กำกับอยู่บนจอ คีย์ที่ระบบเขียนเอง (เช่นเวลาที่เริ่มส่ง) และคีย์ที่มีหน้าจอของตัวเองแล้ว (เทมเพลต ตารางเวลางาน) ที่เหลือขึ้นจอทั้งหมด ค่าความลับขึ้นจอเสมอ เอกสาร discuss ของโปรเจกต์ตัดคีย์ออกเพิ่มได้พร้อมเหตุผล
- **เหตุผล:** ค่าที่ลูกค้าปรับได้อยู่ที่เดียว ส่วนค่าที่เป็นการออกแบบของระบบ (ความยาวสูงสุดของช่อง ขนาดหน้า) ไม่ทำให้หน้าจอรก
- **ถ้าผิด:** แก้ทีหลังได้ — เพิ่มหรือเอาคีย์ออกจาก catalog ใน change ถัดไป ค่าที่เก็บไว้ไม่หาย
- **ถามเมื่อ:** ไม่ถาม

### SET-D03: ค่าไหนอยู่ใน env ค่าไหนอยู่บนจอ
- **คำตอบ:** env เก็บเฉพาะสิ่งที่ระบบต้องมีก่อนเปิดฐานข้อมูลหรือเพื่อคุมความลับ: การเชื่อมต่อฐานข้อมูล กุญแจเซ็นโทเค็นและ cookie กุญแจเข้ารหัสความลับ ค่าที่ต่างกันตามเครื่องที่ติดตั้ง (URL ของพอร์ทัล ที่เก็บไฟล์) และ env ฉุกเฉินของ SET-D22 ค่าอื่นที่ลูกค้าปรับระหว่างใช้งานอยู่บนจอ รวมค่าเชื่อมต่อระบบภายนอกและรหัสผ่านของมัน (เช่น SMTP host, port, ผู้ใช้, รหัส, ผู้ส่ง) และสวิตช์ฟีเจอร์ (เช่น OTP)
- **เหตุผล:** ลูกค้าเปลี่ยนผู้ให้บริการอีเมลหรือเปิดปิด OTP ได้เองโดยไม่ต้องรอคน deploy ส่วนสิ่งที่ถ้าหายแล้วระบบเปิดไม่ได้ หรือถ้ารั่วแล้วความลับทั้งหมดรั่ว ยังอยู่กับคน deploy
- **ถ้าผิด:** แก้ทีหลังได้ — ย้ายค่าระหว่าง env กับจอได้ด้วยกติกาค่าตั้งต้นครั้งแรก (SET-D07)
- **ถามเมื่อ:** เอกสารลูกค้าหรือฝ่ายความปลอดภัยห้ามเก็บรหัสผ่านของระบบอื่นในฐานข้อมูล หรือกำหนดให้ใช้ secret store ของเครื่อง
- **ตัวเลือกอื่น:** b) ค่าเชื่อมต่อและรหัสผ่านของระบบภายนอกอยู่ใน env หรือ secret store เปลี่ยนแล้ว restart ค่าที่เหลืออยู่บนจอ c) ทุกค่าอยู่ใน env ไม่มีหน้าตั้งค่า

### SET-D04: เก็บค่าอย่างไร
- **คำตอบ:** ตาราง `system_setting` หนึ่งแถวต่อคีย์ (ต่อ `{portal}` เมื่อกำกับ `ต่อพอร์ทัล`) เก็บค่า รุ่น และผู้แก้ ตอน start ระบบเติมแถวของคีย์ที่ยังไม่มีด้วยค่าจาก env (SET-D07) หรือค่าเริ่มต้น และไม่ทับค่าที่มีอยู่ แถวไม่ถูกลบ คีย์ที่ออกจาก catalog คงแถวไว้แต่ไม่ถูกอ่าน
- **เหตุผล:** ตารางเดียวเพิ่มคีย์ได้โดยไม่แก้โครง ค่าที่คนตั้งไว้ไม่หายตอน deploy และ Activity Log อ้างแถวเดิมได้เสมอ
- **ถ้าผิด:** แก้ทีหลังได้ — ตัวอ่านค่ามีจุดเดียว ย้ายที่เก็บได้ด้วย migration
- **ถามเมื่อ:** ไม่ถาม

### SET-D05: ค่ามีชนิดอะไรบ้าง
- **คำตอบ:** เจ็ดชนิด: จำนวนเต็มพร้อมช่วงและหน่วย, เปิด/ปิด, ข้อความพร้อมความยาวสูงสุด, list (หนึ่งรายการต่อบรรทัด ตัดช่องว่างหัวท้าย ตัดรายการซ้ำโดยไม่สนตัวพิมพ์ แต่ละรายการผ่านกฎของแพ็กเจ้าของ), ตัวเลือกเดียวจากชุดที่กำหนด, ตัวเลือกหลายข้อจากชุดที่กำหนด (มีจำนวนขั้นต่ำได้) และความลับ แพ็กเจ้าของบอกชนิด ช่วง และกฎ ถ้าไม่บอกความยาวใช้ค่าของแพ็กนี้ ไม่มีทศนิยม แพ็กเจ้าของใช้หน่วยที่เล็กลงแทน
- **เหตุผล:** ชนิดชุดเดียวทำให้ช่องบนจอ การตรวจ และการเก็บเขียนครั้งเดียวแล้วใช้ได้กับทุกแพ็ก
- **ถ้าผิด:** แก้ทีหลังได้ — เพิ่มชนิดใหม่ได้ ช่องชนิดที่หน้าจอไม่รู้จักแสดงเป็นข้อความอ่านอย่างเดียว
- **ถามเมื่อ:** ไม่ถาม

### SET-D06: แต่ละช่องบนจอแสดงอะไร
- **คำตอบ:** ชื่อ (English · ไทย) ช่องกรอกตามชนิด หน่วยข้างค่า ช่วงหรือตัวเลือก ค่าเริ่มต้น และสองบรรทัดใต้ช่อง: "คืออะไร ทำอะไร" กับ "ปรับแล้วเป็นอย่างไร" ทั้งสองภาษา ข้อความทั้งหมดมาจาก API หน้าจอไม่มีชื่อ ช่วง หรือคำอธิบายของตัวเอง
- **เหตุผล:** ผู้ดูแลรู้ผลก่อนกดบันทึกโดยไม่ต้องเปิดเอกสาร และ catalog เป็นที่เดียวที่ต้องแก้
- **ถ้าผิด:** แก้ทีหลังได้ — เป็นการแสดงผล
- **ถามเมื่อ:** ไม่ถาม

### SET-D07: ค่าที่ย้ายจาก env มาไว้บนจอ
- **คำตอบ:** ค่า env เดิมเป็นค่าตั้งต้นครั้งเดียว ตอน start ที่คีย์ยังไม่มีแถว env ว่างหรือไม่ได้ตั้งใช้ค่าเริ่มต้น หลังจากนั้นอ่านจากตารางเท่านั้น env ไม่ทับอีก ถ้า env ยังตั้งไว้และต่างจากที่เก็บ ตอน start เขียน warning หนึ่งบรรทัดที่บอกชื่อ env และคีย์ ไม่บอกค่า
- **เหตุผล:** deploy รุ่นที่ย้ายค่าแล้วระบบทำงานเหมือนเดิมในวันแรก และค่าที่ผู้ดูแลตั้งบนจอไม่ถูก env เก่าทับตอน restart
- **ถ้าผิด:** แก้ทีหลังได้ — ค่าที่เก็บแล้วแก้บนจอได้
- **ถามเมื่อ:** ไม่ถาม

### SET-D08: เก็บความลับอย่างไร
- **คำตอบ:** เข้ารหัสด้วยกุญแจจาก env `SETTINGS_SECRET_KEY` ก่อนลงฐานข้อมูล และถอดรหัสเฉพาะจุดที่ใช้ ไม่อยู่ในคำตอบใดของ API ไม่อยู่ใน log, ข้อความ error, HTML ของหน้า หรือ Activity Log ซึ่งบันทึกแค่ว่าเปลี่ยน (AUDIT-D12) catalog มีความลับแต่ขาดกุญแจหรือกุญแจอ่านไม่ได้: ทุก environment ยกเว้น Development และ Prototype API ไม่ start ส่วน Development และ Prototype ที่ขาดกุญแจ API start ได้ แต่บันทึกค่าความลับไม่ได้ และหน้าตั้งค่าแจ้งว่ายังไม่มีกุญแจ กุญแจที่มีแต่อ่านไม่ได้ไม่ start ทุก environment
- **เหตุผล:** สำเนาฐานข้อมูลหรือ backup ที่หลุดไม่ทำให้รหัสผ่านของระบบอื่นรั่ว และคนที่ดูหน้าจอหรือ log ไม่เห็นความลับ
- **ถ้าผิด:** แก้ยาก — ความลับที่เคยเก็บเป็นข้อความธรรมดาหรือลง log ไปแล้วต้องถือว่ารั่ว ต้องเปลี่ยนรหัสที่ระบบปลายทาง
- **ถามเมื่อ:** ไม่ถาม

### SET-D09: ความลับแสดงและแก้บนจออย่างไร
- **คำตอบ:** แสดงแค่ "Set · ตั้งแล้ว" หรือ "Not set · ยังไม่ได้ตั้ง" กับช่องว่างสำหรับค่าใหม่ ไม่บอกความยาว ช่องว่างตอนบันทึกคือคงค่าเดิม ล้างค่าได้ด้วยปุ่ม Clear ของช่องนั้นเท่านั้นและต้องยืนยัน ความลับไม่ถูกตัดช่องว่างหัวท้าย
- **เหตุผล:** แก้ค่าอื่นในแท็บเดียวกันได้โดยไม่ต้องรู้รหัสเดิม และไม่มีใครล้างรหัสโดยไม่ตั้งใจ
- **ถ้าผิด:** แก้ทีหลังได้ — เป็นการแสดงผลและกติกาของการบันทึก
- **ถามเมื่อ:** ไม่ถาม

### SET-D10: กุญแจความลับหายหรือเปลี่ยน
- **คำตอบ:** ระหว่างเปลี่ยนกุญแจ ใส่กุญแจเก่าไว้ใน `SETTINGS_SECRET_KEY_PREVIOUS` ตอน start ระบบอ่านความลับด้วยกุญแจเก่าแล้วเข้ารหัสใหม่ด้วยกุญแจใหม่ จากนั้นเอากุญแจเก่าออกได้ ความลับที่อ่านไม่ได้ด้วยกุญแจใดไม่ทำให้ระบบล้ม ช่องนั้นขึ้นว่าอ่านไม่ได้ให้กรอกใหม่ งานที่ใช้ค่านั้นถือว่ายังไม่ได้ตั้ง และตอน start เขียน warning บอกชื่อคีย์
- **เหตุผล:** เปลี่ยนกุญแจตามรอบได้โดยไม่ต้องกรอกทุกความลับใหม่ และกุญแจหายแล้วยังเข้าระบบไปกรอกใหม่ได้
- **ถ้าผิด:** แก้ทีหลังได้ — กรอกความลับใหม่บนจอได้เสมอ
- **ถามเมื่อ:** ไม่ถาม

### SET-D11: ค่าที่บันทึกแล้วมีผลเมื่อไร
- **คำตอบ:** ครั้งถัดไปที่ระบบใช้ค่านั้น โดยไม่ restart ระบบอ่านผ่าน cache ที่เครื่องที่บันทึกล้างทันทีหลัง commit และเครื่องอื่นเก็บไว้ไม่เกิน `settings.cache_seconds` วินาที แพ็กเจ้าของบอกว่า "ครั้งถัดไป" ของค่าตัวเองคืออะไร (คำขอถัดไป รอบส่งถัดไป ไฟล์ถัดไป)
- **เหตุผล:** ผู้ดูแลเห็นผลทันทีโดยไม่ต้องมีคน deploy และระบบไม่ต้องอ่านฐานข้อมูลทุกครั้งที่ใช้ค่า ส่วนเครื่องอื่นช้าได้ไม่เกินเวลาที่รู้แน่
- **ถ้าผิด:** แก้ทีหลังได้ — ปรับอายุ cache หรือเปลี่ยนเป็นแจ้งทุกเครื่องได้โดยไม่แตะข้อมูล
- **ถามเมื่อ:** ไม่ถาม

### SET-D12: งานที่เริ่มแล้วใช้ค่าไหน
- **คำตอบ:** ค่าที่อ่านตอนเริ่มงานจนจบงานนั้น หนึ่งคำขอ หนึ่งรอบงาน (รอบส่งอีเมล รอบนำเข้า) หรือหนึ่งการอัปโหลด อ่านค่าที่ใช้ครั้งเดียวตอนเริ่ม งานที่เข้าคิวแล้วแต่ยังไม่เริ่มใช้ค่าที่มีผลตอนเริ่ม ข้อมูลที่บันทึกไว้แล้วไม่ถูกแก้ย้อน เว้นแต่แพ็กเจ้าของสั่ง
- **เหตุผล:** งานหนึ่งไม่ทำครึ่งหนึ่งด้วยค่าเก่าและอีกครึ่งด้วยค่าใหม่ ผลจึงอธิบายได้
- **ถ้าผิด:** แก้ทีหลังได้ — แพ็กเจ้าของเปลี่ยนจุดที่อ่านค่าของงานตัวเองได้
- **ถามเมื่อ:** ไม่ถาม

### SET-D13: ตรวจค่าอย่างไร
- **คำตอบ:** API ตรวจค่าทั้งแท็บตามที่จะเป็นหลังบันทึก (ค่าที่ส่งมารวมกับค่าที่เก็บไว้) ทั้งชนิด ช่วง ตัวเลือก กฎของรายการ ขอบความปลอดภัย และกฎข้ามคีย์ที่แพ็กเจ้าของกำหนด (เช่นต่ำสุดไม่เกินสูงสุด) ตอบทุกข้อผิดพร้อมกัน ต่อคีย์ สองภาษา และไม่บันทึกอะไรเลยถ้ามีข้อผิดแม้ข้อเดียว หน้าจอตรวจแค่ชนิดของช่องกรอก
- **เหตุผล:** ผู้ดูแลแก้ทุกข้อในรอบเดียว และกฎอยู่ที่ server ที่เดียว จึงเรียก API ตรงก็ข้ามกฎไม่ได้
- **ถ้าผิด:** แก้ทีหลังได้ — เพิ่มกฎได้โดยไม่เปลี่ยนที่เก็บ
- **ถามเมื่อ:** ไม่ถาม

### SET-D14: ค่าความปลอดภัยปรับหลวมลงได้แค่ไหน
- **คำตอบ:** ค่าที่แพ็กเจ้าของกำกับ `ห้ามต่ำกว่า`, `ห้ามเกิน` หรือ `ห้ามปิด` ห้ามหลวมกว่าขอบนั้น ไม่เขียนค่าคือขอบเป็นค่าเริ่มต้น แพ็กที่เขียนรวมว่าห้ามหลวมกว่าค่าเริ่มต้นโดยไม่บอกทาง ใช้ปลายช่วงใน params.md เป็นขอบ เมื่อเอกสารลูกค้ากำหนดค่าเริ่มต้นใหม่ ขอบที่ไม่ได้เขียนค่าเลื่อนตาม ขอบที่เอกสารลูกค้าระบุแทนขอบของแพ็ก ช่วงที่ API ตอบเริ่มที่ขอบนี้ ค่าที่หลวมกว่าถูกปฏิเสธพร้อมข้อความบอกขอบ แพ็กนี้บังคับคำกำกับแบบเดียวกันทุกคีย์ ส่วนคีย์ไหนเป็นค่าความปลอดภัยแพ็กเจ้าของเป็นคนบอก
- **เหตุผล:** ลูกค้าเข้มขึ้นได้เสมอ แต่ไม่มีใครทำให้ระบบอ่อนกว่าที่ตกลงไว้จากหน้าจอ
- **ถ้าผิด:** แก้ยาก — ระหว่างที่ค่าหลวมลง ระบบเสี่ยง และผลที่เกิดแล้ว (บัญชีที่ถูกเดารหัส) ย้อนไม่ได้
- **ถามเมื่อ:** เอกสารลูกค้าให้ผู้ดูแลตั้งค่าความปลอดภัยหลวมกว่าค่าเริ่มต้นได้
- **ตัวเลือกอื่น:** b) ตั้งได้ทั้งช่วงของแพ็กเจ้าของ ค่าที่หลวมกว่าขอบต้องยืนยันและลง Activity Log c) ค่าความปลอดภัยไม่ขึ้นจอ อยู่ในโค้ด

### SET-D15: การเปลี่ยนแบบไหนต้องยืนยัน
- **คำตอบ:** การเปลี่ยนที่แพ็กเจ้าของกำกับ `ทำให้ว่างต้องยืนยัน` (list ที่มีรายการกลายเป็นว่าง เช่น allow-list ผู้รับ) `ปิดต้องยืนยัน` หรือ `เปิดต้องยืนยัน` (เช่นปิด OTP) และการล้างความลับทุกตัว หน้าจอแสดงกล่องยืนยันที่บอกทุกการเปลี่ยนนั้นเป็นประโยค (ชื่อ ค่าเดิม → ค่าใหม่ และผล) ก่อนส่ง และ API ปฏิเสธการเปลี่ยนเหล่านี้ถ้าคำขอไม่บอกว่ายืนยันแล้ว
- **เหตุผล:** การเปลี่ยนที่ทำให้อีเมลไปถึงคนจริงทุกคนหรือปิดชั้นความปลอดภัยต้องเป็นความตั้งใจ และ API กันเองได้แม้มีคนเรียกตรงโดยไม่ผ่านหน้าจอ
- **ถ้าผิด:** แก้ทีหลังได้ — เพิ่มหรือเอาคำกำกับออกในแพ็กเจ้าของ
- **ถามเมื่อ:** ไม่ถาม

### SET-D16: บันทึกอย่างไร และเมื่อสองคนแก้พร้อมกัน
- **คำตอบ:** บันทึกทีละแท็บใน transaction เดียว ส่งเฉพาะค่าที่ต่างจากที่อ่านมา พร้อมรุ่นของแต่ละค่า รุ่นไม่ตรงกับที่เก็บแล้วตอบ 409 ไม่บันทึกอะไร หน้าจอบอกว่ามีคนแก้ก่อนพร้อมปุ่มโหลดใหม่ ร่างยังอยู่จนกดโหลดใหม่ Save ปิดเมื่อไม่มีอะไรต่าง Cancel คืนค่าที่อ่านมา เปลี่ยนแท็บหรือออกจากหน้าตอนมีร่างต้องถามก่อน
- **เหตุผล:** รุ่นต่อค่าทำให้สองคนที่แก้คนละค่าบันทึกได้ทั้งคู่ แต่คนที่แก้ค่าเดียวกันไม่ทับกันเงียบๆ (AUDIT-D10)
- **ถ้าผิด:** แก้ทีหลังได้ — เปลี่ยนเป็นรุ่นต่อแท็บได้โดยไม่เปลี่ยนค่าที่เก็บ
- **ถามเมื่อ:** ไม่ถาม

### SET-D17: การบันทึกลง Activity Log อย่างไร
- **คำตอบ:** หนึ่งการบันทึกเป็นหนึ่งรายการ `SaveSettings` ชนิดเอกสาร `SystemSetting` id เอกสารเป็นรหัสแท็บ มีค่าเก่าและค่าใหม่ของทุกคีย์ที่เปลี่ยน พร้อมพอร์ทัลเมื่อเป็นค่าต่อพอร์ทัล ความลับบันทึกแค่ว่าเปลี่ยน การบันทึกที่ไม่เปลี่ยนอะไรไม่ลง log ผลที่แพ็กเจ้าของผูกกับการเปลี่ยน (เช่นคำนวณวันหมดอายุใหม่ทุกบัญชี) ทำใน transaction เดียวกันและลงรายการของตัวเอง ถ้าล้มก็ไม่บันทึกอะไร
- **เหตุผล:** ผู้ตรวจตอบได้ว่าใครเปลี่ยนนโยบายอะไร เมื่อไร จากค่าไหนเป็นค่าไหน โดยใช้จอ Activity Log ที่มีอยู่
- **ถ้าผิด:** แก้ยาก — การเปลี่ยนที่ไม่ได้บันทึกไว้ย้อนหาไม่ได้
- **ถามเมื่อ:** ไม่ถาม

### SET-D18: คืนค่าเริ่มต้นอย่างไร
- **คำตอบ:** ปุ่ม Default ข้างช่องใส่ค่าเริ่มต้นของคีย์นั้นลงร่าง ปุ่ม Reset tab ใส่ค่าเริ่มต้นของทุกคีย์ในแท็บลงร่าง ยกเว้นความลับ แล้วกด Save ตามปกติ จึงผ่านการตรวจ การยืนยัน และ Activity Log เหมือนการแก้อื่น ค่าเริ่มต้นคือค่าของโปรเจกต์ (ค่าที่เอกสารลูกค้ากำหนด ถ้ามี) ไม่ใช่ค่าของแพ็ก
- **เหตุผล:** ผู้ดูแลถอยกลับได้ง่ายเมื่อปรับแล้วไม่ดี และไม่มีทางลัดที่ข้ามการตรวจหรือ log
- **ถ้าผิด:** แก้ทีหลังได้ — เป็นปุ่มบนจอ
- **ถามเมื่อ:** ไม่ถาม

### SET-D19: ใครดูและแก้หน้าตั้งค่าได้
- **คำตอบ:** หน้าตั้งค่าเป็นหนึ่งหน้าจอในตารางสิทธิ์ มีช่อง View และ Manage `{superadmin}` ถือทั้งสองช่องตั้งแต่ seed ผู้ถือ View เห็นทุกแท็บแบบอ่านอย่างเดียว ผู้ถือ Manage บันทึกได้ทุกแท็บ ไม่มี View แล้วไม่มีเมนู เปิดด้วย URL ได้แผง no-access และ API ตอบ 403 พร้อมรายการ `AccessDenied`
- **เหตุผล:** ค่าบนหน้านี้กระทบทั้งระบบ คนที่แก้ได้ควรน้อยและชัด
- **ถ้าผิด:** แก้ยาก — แยกสิทธิ์ทีหลังต้องมี migration คัดลอกสิทธิ์ให้กลุ่มเดิม และเปลี่ยนว่าใครแก้อะไรได้
- **ถามเมื่อ:** เอกสารลูกค้าให้คนละกลุ่มดูแลค่าคนละเรื่อง เช่นฝ่ายบุคคลดูแลนโยบายรหัสผ่าน ฝ่ายไอทีดูแลอีเมล
- **ตัวเลือกอื่น:** b) ช่อง View และ Manage แยกต่อแท็บ c) ไม่อยู่ในตารางสิทธิ์ เปิดได้เฉพาะ `{superadmin}`

### SET-D20: ค่าต่อพอร์ทัลเก็บและแสดงอย่างไร
- **คำตอบ:** ค่าที่แพ็กเจ้าของกำกับ `ต่อพอร์ทัล` มีแถว ค่า และรุ่นแยกของแต่ละ `{portal}` บนจอเป็นช่องเดียวที่มีช่องกรอกหนึ่งช่องต่อพอร์ทัล กฎข้ามคีย์ตรวจภายในพอร์ทัลเดียวกัน พอร์ทัลที่เพิ่มทีหลังได้ค่าเริ่มต้นตอน start ค่าที่ไม่กำกับมีค่าเดียวทั้งระบบ
- **เหตุผล:** พอร์ทัลของพนักงานกับของคนนอกมักต้องการนโยบายต่างกัน และผู้ดูแลเห็นค่าทุกพอร์ทัลเทียบกันในที่เดียว
- **ถ้าผิด:** แก้ทีหลังได้ — แยกหรือรวมค่าต่อพอร์ทัลได้ด้วย migration ของแถว
- **ถามเมื่อ:** ไม่ถาม

### SET-D21: ค่าที่เก็บไว้อยู่นอกช่วงของรุ่นใหม่
- **คำตอบ:** ตอน start ค่าที่อยู่นอกช่วงหรือความยาว หลวมกว่าขอบความปลอดภัย หรือเป็นตัวเลือกที่ไม่มีแล้ว ถูกปรับเป็นค่าที่ใกล้ที่สุดที่ยังรับได้ (ปลายช่วงหรือขอบที่ใกล้ที่สุด ตัดตัวเลือกที่หายไปออก ตัวเลือกเดียวหรือตัวเลือกที่เหลือไม่ถึงขั้นต่ำกลับเป็นค่าเริ่มต้น) ในนาม System ลง Activity Log และเขียน warning บอกคีย์ ค่าเดิม และค่าใหม่
- **เหตุผล:** ระบบไม่ทำงานด้วยค่าที่รุ่นใหม่ไม่รับ และไม่ต้องรอใครเปิดจอมาแก้
- **ถ้าผิด:** แก้ทีหลังได้ — ผู้ดูแลตั้งค่าใหม่บนจอได้ทันที
- **ถามเมื่อ:** ไม่ถาม

### SET-D22: เข้าหน้าตั้งค่าไม่ได้แล้วแก้ค่าอย่างไร
- **คำตอบ:** แพ็กเจ้าของกำหนด env ฉุกเฉินให้คีย์ที่อาจทำให้เข้าระบบไม่ได้ (เช่นปิด OTP ทุกพอร์ทัลเมื่ออีเมลล่ม) env นี้บังคับค่าที่แพ็กเจ้าของกำหนดตั้งแต่ start โดยไม่แก้ค่าที่เก็บ หน้าจอแสดงว่าช่องนั้นถูก env บังคับอยู่ เอา env ออกแล้ว restart ค่าที่เก็บกลับมามีผล env ที่ย้ายมาเป็นค่าบนจอไม่ทับค่าที่เก็บไม่ว่ากรณีใด
- **เหตุผล:** เมื่อเปิด OTP แล้วส่งรหัสไม่ได้ จะไม่มีใครเข้าระบบไปปิดได้ คน deploy ต้องมีทางออกที่เห็นได้ชัด และถอนได้โดยค่าที่ผู้ดูแลตั้งไว้ไม่หาย
- **ถ้าผิด:** แก้ทีหลังได้ — เพิ่ม env ฉุกเฉินให้คีย์อื่นในแพ็กเจ้าของได้
- **ถามเมื่อ:** ไม่ถาม

### SET-D23: มีหน้าประวัติหรือปุ่มย้อนค่าไหม
- **คำตอบ:** ไม่มี ประวัติดูในจอ Activity Log โดยกรองชนิดเอกสาร `SystemSetting` ย้อนค่าทำโดยกรอกค่าเดิมแล้วบันทึก
- **เหตุผล:** Activity Log มีค่าเก่าและค่าใหม่ครบแล้ว หน้าเพิ่มอีกหน้าไม่ได้ข้อมูลใหม่
- **ถ้าผิด:** แก้ทีหลังได้ — เพิ่มแท็บประวัติที่อ่านจาก Activity Log ได้
- **ถามเมื่อ:** เอกสารลูกค้าขอหน้าประวัติของค่าตั้ง หรือปุ่มย้อนกลับเป็นค่าก่อนหน้า
- **ตัวเลือกอื่น:** b) แท็บประวัติในหน้าตั้งค่า อ่านจาก Activity Log ของแท็บนั้น c) b และปุ่มย้อนค่าที่ใส่ค่าเดิมลงร่างให้บันทึก
