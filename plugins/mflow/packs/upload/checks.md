# upload checks

สิ่งที่ลองตอนทดสอบใช้งาน แต่ละข้อเป็น test หรือ acceptance criterion ได้

1. แนบ PDF ขนาดเล็กบนฟอร์มสร้าง `{record}` ใหม่ แล้วบันทึก: รายการใหม่มีไฟล์นั้น ดาวน์โหลดได้ชื่อเดิม และ Activity Log มีรายการเดียวของการบันทึกที่บอกชื่อไฟล์
2. เปลี่ยนนามสกุล PDF เป็น `.xlsx` แล้วอัปโหลด และเปลี่ยนไฟล์ `.zip` เป็น `.docx` แล้วอัปโหลด: ทั้งสองถูกปฏิเสธพร้อมข้อความ และไม่มีอะไรถูกเก็บ
3. อัปโหลดไฟล์ 0 byte และไฟล์ที่ใหญ่กว่าขนาดต่อไฟล์ 1 MB: ถูกปฏิเสธ ข้อความของไฟล์ใหญ่บอกขนาดที่รับ
4. ติ๊ก .png ออกบนหน้าตั้งค่า: ไฟล์ .png ที่แนบไว้แล้วยังดาวน์โหลดได้ ไฟล์ .png ใหม่ถูกปฏิเสธ และช่องแนบไฟล์บอกชนิดที่รับใหม่โดยไม่ต้อง deploy
5. ส่งชื่อไฟล์ `..\..\quote.pdf` และชื่อภาษาไทยยาว 260 ตัวอักษร: ชื่อที่แสดงไม่มี path ชื่อยาวถูกตัดแต่ยังลงท้ายด้วยนามสกุลเดิม และ key ในที่เก็บไม่มีส่วนใดของชื่อ
6. ผู้ใช้ที่ไม่เห็นรายการ ใส่รหัสไฟล์ของรายการนั้นใน address: ได้ 404 แบบเดียวกับรหัสที่ไม่มีจริง
7. ดาวน์โหลดไฟล์แล้วดู header: มี `Content-Disposition: attachment` พร้อมชื่อไทยที่อ่านออก `X-Content-Type-Options: nosniff` และไม่มี URL ของที่เก็บไฟล์ในคำตอบใด
8. อัปโหลดไฟล์แล้วปิดฟอร์มโดยไม่บันทึก แล้วเลื่อนนาฬิกาเกินอายุที่พัก: งานล้างลบไฟล์และแถวที่พัก และ Activity Log ไม่มีรายการใหม่
9. แนบไฟล์จนครบจำนวนต่อรายการ แล้วแนบอีกไฟล์: ได้ `TOO_MANY_FILES` ไฟล์ที่พักยังอยู่ และเอาไฟล์เก่าออกหนึ่งไฟล์แล้วแนบได้
10. เอาไฟล์ออกจากรายการ: ไฟล์หายจากรายการ แถวผูกมี `deleted_by` แถวทะเบียนยังอยู่ และหลังอายุเก็บของไฟล์ที่เอาออก เนื้อไฟล์ถูกล้างและมี `purged_at`
11. เอารหัสที่พักของผู้ใช้อื่นไปบันทึกกับรายการ: ถูกปฏิเสธ และไม่มีไฟล์ใดถูกผูก
12. (เมื่อสแกน) อัปโหลดไฟล์ทดสอบไวรัสมาตรฐาน และอัปโหลดตอนตัวสแกนหยุด: ไฟล์แรกถูกปฏิเสธว่าไม่ผ่านการตรวจไวรัส ไฟล์หลังได้ข้อความให้ลองใหม่ ทั้งสองไม่ถูกเก็บ
13. (เมื่อมี `{org_portal}`) บัญชีคนนอกอัปโหลดเกินจำนวนต่อชั่วโมง: ได้ 429 พร้อมเวลาที่ลองใหม่ได้ ส่วนบัญชีพนักงานไม่ถูกจำกัด
14. (test) ส่งคำขอใหญ่กว่าเพดานของ server: ถูกตัดก่อนอ่านจบ และหน่วยความจำของ server ไม่พุ่งตามขนาดไฟล์
15. (test) เพิ่ม endpoint ที่อ่าน `stored_file` ตรงโดยไม่ผ่านตารางผูก: architecture test ล้มและบอกตำแหน่ง
