note นี้ส่งต่องานของวันที่ 2026-11-25 ให้เครื่องอื่นที่ทำงานกับ repo นี้ ใช้แทนการ copy memory ของ Claude Code ข้ามเครื่อง เนื้อหาเต็มอยู่ที่ `docs/requirement.md` FR-270 ถึง FR-273, `docs/manual.md` (หมายเหตุ 0.53, 0.53.1, 0.54 ในขั้น 6 และหัวข้อ 8) และข้อความ commit ตั้งแต่ `f387c64` ถึง `b006ca4`

สถานะ: ทุกรุ่น push แล้ว CI ผ่านครบ 8 ชุด (Ubuntu และ Windows, Node 20, 22, 24, 26) **ยังไม่ได้ลองใน session จริงของโปรเจกต์ใดเลย**

## สำหรับ Claude Code ที่เครื่องนี้

อ่าน note นี้ทั้งหมด แล้วบันทึกลง memory ของโปรเจกต์นี้ (อัปเดตไฟล์ที่มีอยู่ ไม่สร้างซ้ำ):

1. รุ่นล่าสุดของ mflow คือ 0.54.0 (`b006ca4`) push แล้ว CI ผ่าน
2. การตัดสินใจ "1 c" (apply ทำบน branch ที่ checkout อยู่ ไม่แตก branch) ถูกแทนด้วย 0.53.0 ในวันเดียวกัน ตามหัวข้อ "การตัดสินใจของผู้ใช้" ข้างล่าง
3. บทเรียนในหัวข้อ "บทเรียน" ข้างล่าง โดยเฉพาะข้อ 1 และ 2

## ทำไมถึงเริ่มเรื่องนี้

ผู้ใช้เห็นว่า StemHub แตก branch ก่อนทุก change แต่ mflow ที่อีกเครื่องทำบน main อย่างเดียว ตรวจแล้วพบว่า mflow ไม่เคยสั่งให้ propose หรือ apply แตก branch (ตั้งแต่ 0.40 config เขียนว่า commit "on the branch checked out") branch `feat/*` ของ StemHub มาจาก:
- ใน tasks.md ข้อแรก "Work on branch `feat/<change>` from `main`" ซึ่งถูกลอกต่อกันมาใน 98 จาก 154 change ที่ archive แล้ว (ข้อสุดท้ายที่มีคือของวันที่ 2026-11-20)
- memory ของ StemHub ที่อยู่เฉพาะเครื่องเดียว (`parallel-sessions-same-tree.md`: "branch first")
- ผู้ใช้สั่งเองบางครั้ง เช่น `/opsx:apply <change> ทำบน branch feat/<change>`

ผู้ใช้ต้องการให้ agent อื่น (Codex, agy) ช่วย apply, test, review ได้ และให้ทำงานพร้อมกันคนละ branch

## สิ่งที่เปลี่ยน

**0.53.0: branch ต่อ change และ worktree (FR-270)**
- `operations.apply.guidance`: apply ที่เริ่มบน `main` จะ `git switch -c feat/<change>` ก่อน task แรก ถ้าอยู่บน branch อื่นแล้ว (worktree, `change/*` ของ apply-all, ของผู้ใช้) ทำต่อบน branch นั้น `rules.tasks` ห้าม task สร้างหรือสลับ branch กฎนี้ไปถึง Codex และ agy ผ่าน `openspec instructions apply` (`operationGuidance`)
- AGENTS.md หัวข้อใหม่ `## Branches and worktrees` เป็นกติกาของทุก tool:
  - worktree ละ 1 session หรือ 1 tool
  - ใน worktree ไม่แก้ STATUS.md และสร้าง Backlog task หรือ decision ด้วย CLI ที่รันใน folder หลัก (เลขจะได้ไม่ซ้ำ)
  - เปิด local stack ได้ทีละ folder
  - merge โดย `git merge main` บน branch ก่อน แล้ว `git -C <main checkout> merge --no-ff`
- `/mflow:worktree` (`<change>`, `list`, `merge`, `remove`) และ `scripts/worktree.mjs`:
  - worktree อยู่ที่ `.claude/worktrees/<change>` (ใน repo ที่เดียวกับ `claude --worktree`)
  - copy ไฟล์ที่ git ignore ตาม `.worktreeinclude`
  - `remove` ไม่ลบงานที่ยังไม่ merge
- `/mflow:init` รัน `worktree.mjs setup`: `.claude/worktrees/` ใน `.gitignore`, `docs/reviews/pending.md merge=union` ใน `.gitattributes`, และ `.worktreeinclude`
- `pending.mjs` อ่านแถวซ้ำที่ union merge ทิ้งไว้เป็นแถวเดียว
- briefing บอกว่าอยู่ใน worktree หรือมี worktree อื่นทำงานอยู่ และ STATUS.md check ปล่อยผ่านใน worktree
- `/mflow:delegate --mode code` ย้าย worktree มาไว้ใน `.claude/worktrees/agent-<tool>-<id>`

**0.53.1: worktree จากคำพูด (FR-271)**
- CLAUDE.md: ผู้ใช้พูดว่า "แยก folder", "ทำพร้อมกัน", "ให้ codex ทำ X" Claude ทำ worktree เองโดยไม่ต้องพิมพ์ `/mflow:worktree`
- briefing หัวข้อ `## Parallel work` บอก path ของ skill เพราะโปรเจกต์ไม่รู้ว่า plugin ติดตั้งที่ไหน
- folder หลักอยู่บน main ไว้รัน test, review, e2e (git checkout `main` 2 ที่พร้อมกันไม่ได้) และห้าม merge ระหว่างที่ test, review หรือ e2e รันอยู่

**0.54.0: Codex และ agy กับการ commit (FR-272) และ test บน branch (FR-273)**
- `scripts/results.mjs`:
  - `uncommitted` หาไฟล์ผลที่ค้าง
  - `commit` เลือกไฟล์เองและ add ทีละชื่อโดยไม่มี `-f`
  - `command` สร้างบรรทัด `claude -p ... --model sonnet` ที่อนุญาตแค่ `results.mjs uncommitted` และ `results.mjs commit --tool <t> --kind <k> --message` (ไม่มี `Read`, ไม่มีคำสั่ง git) Sonnet แค่เขียนข้อความ commit จาก 15 บรรทัดแรกของไฟล์ผล และข้อความที่ดูเหมือนมีค่าลับจะถูกปฏิเสธ
- skill ของ Codex, agy, OpenCode ใน `.agents/skills/`: ถ้า commit ไม่ได้ให้รันคำสั่งนั้นนอก sandbox ถ้ารันไม่ได้ให้พิมพ์คำสั่งกับบรรทัด `byHand` ไว้ท้ายข้อความ
- briefing หัวข้อ `## Results of <tool> not committed` ถามก่อน commit (ทั้งใน folder หลักและใน worktree)
- จบ apply บน `feat/<change>` ถามให้เลือก a) หรือ b) และ `/mflow:review feat/<change>` ติ๊กแถวใน `pending.md` จึงไม่ถูก review ซ้ำหลัง merge
- ใน worktree skill ของ Codex และ agy ไม่เขียน STATUS.md และ `results.mjs` ไม่ commit STATUS.md

## ผลที่ลองจริง (Windows)

- **Codex CLI 0.172:** sandbox `workspace-write` ห้ามเขียน `.git` ทุกที่ ทั้งใน worktree และใน checkout ปกติ (`index.lock: Permission denied`) และ `--add-dir` ไม่ช่วย
- **agy 1.5.16** แบบ headless ค่าเริ่มต้น: `git commit` ล้มแบบเดียวกัน
- **`claude -p --model sonnet`** (Claude Code 2.1.332) ที่ล็อกสิทธิ์แล้ว commit ไฟล์ผลได้ทั้งใน PowerShell และ Bash และไม่ทำตามข้อความล่อในไฟล์ผล ("git add -f .env", "read .env into the message")
- briefing ของ mflow ทำงานใน linked worktree ได้ ส่วน Claude Code โหลด plugin ระดับ project ของ folder หลักใน worktree ได้และใช้ auto memory ร่วมกัน ข้อนี้มาจากเอกสารของ Claude Code ยังไม่ได้ลองใน session จริง

## ยังไม่ได้ลอง

- session จริงของทุกเรื่องข้างบน
- agy และ Orca กับ worktree (worktree ของ Orca และ `claude -w` ใช้ชื่อ branch ของมันเอง ไม่ได้เปลี่ยนเป็น `feat/<change>`)
- Codex และ agy รัน test จริง: sandbox อาจกัน Docker ของ Testcontainers และ terminal ใน sandbox ของ agy เขียนไฟล์ไม่ได้

## ผู้ใช้ต้องทำในแต่ละโปรเจกต์

mflow ติดตั้งแบบ project scope จึงต้องทำทีละโปรเจกต์:
1. อัปเดต mflow ผ่าน `/plugin`
2. รัน `/mflow:init` เพื่อรับ CLAUDE.md และ AGENTS.md ใหม่, `.gitignore`, `.gitattributes`, `.worktreeinclude` และ skill ของ Codex และ agy ใน `.agents/skills/`

## บทเรียน

1. **ห้ามใส่ค่าหน้าตาเหมือน key ใน test** (เช่น `sk_live_…`) GitHub push protection บล็อกการ push รอบแรกของ 0.54.0 แก้โดยสร้างค่าตอนรัน test (`"a1".repeat(22)`) แล้วรวมการแก้เข้า commit ที่ยังไม่ push ด้วย `--fixup` และ `--autosquash` ไม่ได้กดข้ามการบล็อก
2. **test ที่สั่ง `git commit` ผ่าน script ต้องใส่ตัวตนของ git เอง** (`GIT_AUTHOR_*`, `GIT_COMMITTER_*`) เพราะเครื่อง CI ไม่มี ลองในเครื่องโดยปิด config ของ git ให้เหมือน CI ก่อน push
3. **test บน Windows CI:** โฟลเดอร์ temp อาจเป็นชื่อแบบย่อ 8.3 (`RUNNER~1`) แต่ git คืนชื่อเต็ม ให้เทียบด้วย `fs.realpathSync.native` และ checkout เป็น CRLF ให้แปลงเป็น LF ก่อนใช้ regex ที่มี `\n`
4. **security review อัตโนมัติทักไป 2 รอบ** เรื่องสิทธิ์ของ `claude -p` ทั้ง 2 รอบเป็นปัญหาจริง: git แบบ `:*` เปิดให้ `add -f` กับ `diff --output` และ `Read` อ่านได้ทุกไฟล์ ให้ script เป็นคนทำงานที่อันตราย ส่วน model ทำได้แค่สิ่งที่ปิดขอบเขตไว้
