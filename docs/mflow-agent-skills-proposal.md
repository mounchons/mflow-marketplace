# ข้อเสนอ: ให้ Codex และ OpenCode เรียก `mflow-test` และ `mflow-review` ได้

- วันที่เสนอ: 2026-10-19
- สถานะ: ผู้ใช้ตอบ Q1–Q5 ตามคำแนะนำ (2026-10-19) และสร้างแล้วใน mflow 0.33.0 (FR-218 ถึง FR-221) ลองกับ Codex 0.162.1 แล้ว ยังไม่ได้ลองกับ OpenCode
- เป้าหมายเวอร์ชัน: mflow 0.33.0
- อ้างอิง: `docs/mflow-asbuilt-review-proposal.md` (DOC-MFLOW-ASBUILT-001), `docs/requirement.md` §13
- ตรวจกับ: Codex CLI 0.162.1 บนเครื่องนี้, เอกสาร skill ของ OpenCode (opencode.ai/docs/skills) และของ Codex (learn.chatgpt.com/docs/build-skills), skill ของ OpenSpec ใน StemHub (อ่านอย่างเดียว)

## 1. สรุป

`/mflow:test` และ `/mflow:review` เป็น skill ของ Claude Code อยู่แล้ว (`plugins/mflow/skills/test/SKILL.md`, `review/SKILL.md`) ไม่ใช่ command แยก ส่วน Codex และ OpenCode **อ่าน skill จากโฟลเดอร์เดียวกัน** คือ `.agents/skills/<ชื่อ>/SKILL.md` ใน repo ดังนั้นไม่ต้องทำสองชุด: mflow สร้างโฟลเดอร์ skill ชุดเดียวลงโปรเจกต์ แล้วทั้งสองเครื่องมือใช้ร่วมกัน

| เครื่องมือ | อ่าน skill จาก | เรียกอย่างไร |
|---|---|---|
| Claude Code | plugin (`skills/test/`) | `/mflow:test` (เหมือนเดิม) |
| Codex | `.agents/skills/mflow-test/` | `$mflow-test` หรือเลือกจาก `/skills` |
| OpenCode | `.agents/skills/mflow-test/` (agent-compatible path) | `/mflow-test` ใน TUI |

งานจริงมีสองส่วน: (1) script ที่สร้าง skill สองตัวนี้ลงโปรเจกต์ (2) ปรับฝั่ง Claude ให้รับผล test และ review ที่เครื่องมืออื่นทำ ส่วนนี้ต้องให้ผู้ใช้ตัดสินก่อน (§7)

ขอบเขตคือสองคำสั่งนี้เท่านั้น script เดียวกันขยายไปคำสั่งอื่นได้ภายหลัง

## 2. ใครทำอะไร หลังสร้างเสร็จ

| ขั้น | ใคร | ทำอะไร |
|---|---|---|
| 1 | Claude Code | `/mflow:init` สร้างหรืออัปเดต `.agents/skills/mflow-test/` และ `mflow-review/` (ถามก่อนเขียนเหมือนไฟล์อื่นของ init) |
| 2 | คุณ | commit โฟลเดอร์นั้นพร้อม repo |
| 3 | Codex / OpenCode | `$mflow-test` หรือ `/mflow-test`: รัน test ทั้งชุดทีละส่วน บันทึกลง `docs/reviews/tests/` พร้อม `By: codex` |
| 4 | Codex / OpenCode หรือ Claude | `$mflow-review <branch>` หรือ `/mflow:review <branch>`: ใช้ผล test ที่ commit เดียวกัน (ไม่ว่าใครรัน) แล้วเขียนรายงานลง `docs/reviews/code/` พร้อม `Reviewer:` และ `Author:` |
| 5 | คุณ | merge เมื่อรายงานเป็น approve และคุณตกลง |

ตัวอย่างการใช้คู่กัน: Claude เขียนโค้ดใน session หนึ่ง แล้ว Codex รัน test ราว 40 นาทีและรีวิวในอีก terminal เครื่องมือที่ตรวจไม่ใช่ตัวที่เขียน และ test ไม่ไปกิน session ของ Claude

## 3. โครงไฟล์ที่สร้างลงโปรเจกต์

```
.agents/skills/
├─ mflow-test/
│   ├─ SKILL.md
│   ├─ agents/openai.yaml          ← Codex: ห้ามเรียกเองจากการเดาคำสั่ง
│   └─ references/stacks.md        ← คำสั่ง build/test ตาม stack (สำเนาจาก skills/init/references)
└─ mflow-review/
    ├─ SKILL.md
    ├─ agents/openai.yaml
    ├─ references/stacks.md, responsive.md, prototype-data.md
    └─ scripts/discuss.mjs, lib.mjs  ← สำหรับ "Checks in use" (discuss.mjs checks)
```

- `mflow-test` **ไม่ต้องใช้ script** ใช้แค่ git กับคำสั่งใน `## Commands` ของ AGENTS.md
- `mflow-review` ใช้ script สองไฟล์ (`discuss.mjs` import `./lib.mjs`) ขอบเขตจึงเล็ก
- ไม่แตะ `openspec-*` และ `.openspec-target` ที่ OpenSpec วางไว้ในโฟลเดอร์เดียวกัน

## 4. Frontmatter ที่ทั้งสองเครื่องมือรับ

OpenCode รับเฉพาะ `name`, `description`, `license`, `compatibility`, `metadata` และห้ามเพิ่ม field อื่นระดับบน `disable-model-invocation` ของ Claude จึงใส่ไม่ได้ กฎ "เรียกเมื่อผู้ใช้สั่งเท่านั้น" ย้ายไปไว้ที่ของแต่ละเครื่องมือ:

```yaml
---
name: mflow-test
description: <ข้อความเดียวกับ skill ของ Claude>
compatibility: Generated by mflow for Codex and OpenCode; Node 20+ and git.
metadata:
  mflow/generated: "0.33.0"
  opencode/slash: "true"
  opencode/autoinvoke: "false"
---
```

```yaml
# agents/openai.yaml (Codex)
policy:
  allow_implicit_invocation: false
```

- ชื่อตรงกฎของ OpenCode (`^[a-z0-9]+(-[a-z0-9]+)*$` และตรงกับชื่อโฟลเดอร์)
- description ไม่เกิน 1024 ตัวอักษร (ตอนนี้ test 342, review 305) script ตรวจความยาวทุกครั้งที่สร้าง
- ค่าใน `metadata` เป็นข้อความทั้งหมดตามที่ OpenCode กำหนด

## 5. Script ที่สร้าง skill (`agent-skills.mjs`)

`/mflow:init` เรียก `node agent-skills.mjs --root . [--dry-run]` ได้ผลเป็นแผนก่อน แล้วเขียนเมื่อผู้ใช้ตกลง

**การแปลงเนื้อหา:** แทนข้อความแบบระบุตัวเป็นรายการ ไม่เขียนเนื้อหาใหม่

| ในต้นฉบับ | ใน skill ที่สร้าง |
|---|---|
| `${CLAUDE_PLUGIN_ROOT}/skills/init/references/stacks.md` | `.agents/skills/mflow-test/references/stacks.md` (หรือของ mflow-review) |
| `${CLAUDE_PLUGIN_ROOT}/scripts/discuss.mjs` | `.agents/skills/mflow-review/scripts/discuss.mjs` |
| `/mflow:test`, `/mflow:review` | "`/mflow:test` ใน Claude Code, `$mflow-test` ใน Codex, `/mflow-test` ใน OpenCode" |
| ย่อหน้า "open a second Claude Code session" | ข้อความกลาง: เปิดอีก session ของเครื่องมือเดิมได้ |

**ส่วนเสริมท้ายไฟล์ (adapter)** ใส่ต่อท้ายเนื้อหาเดิม:
- path ทั้งหมดเป็น path จาก root ของ repo ให้รันคำสั่งจาก root
- ที่นี่ไม่มี hook ของ mflow: เขียน log ใน STATUS.md เองตาม "Session ritual" ของ AGENTS.md
- ถามผู้ใช้เป็นข้อความธรรมดา
- บันทึก `By: <ชื่อเครื่องมือ>` ใน record ของ test และ `Reviewer:` กับ `Author:` ในรายงาน review
- `e2e` ไม่รองรับที่นี่ (§7 Q4)

**เหตุที่ใช้ path จาก root:** เอกสารของทั้ง Codex และ OpenCode ไม่ได้บอกว่า path แบบ relative ใน SKILL.md อ้างจากโฟลเดอร์ skill หรือจาก working directory ส่วน agent ทั้งสองรันคำสั่งจาก root ของ repo อยู่แล้ว จึงใช้ path จาก root ซึ่งไม่ต้องเดา

**ความปลอดภัยในการเขียน:**
- เขียนทับได้เฉพาะโฟลเดอร์ที่มี `metadata.mflow/generated` อยู่แล้ว โฟลเดอร์ชื่อเดียวกันที่ไม่มี marker (skill ของผู้ใช้เอง) จะไม่ถูกแตะ และบอกผู้ใช้
- ไม่เขียนผ่าน link ที่ชี้ออกนอกโปรเจกต์ (`realInside` แบบเดียวกับ script อื่น)
- รันซ้ำแล้วได้ผลเดิม ไม่เขียนถ้าไม่มีอะไรเปลี่ยน
- `doctor` เตือนเมื่อ marker เก่ากว่า plugin: "รัน `/mflow:init` เพื่ออัปเดต skill ของ Codex/OpenCode"

## 6. ฝั่ง Claude ที่ต้องปรับ

- `skills/review/SKILL.md` ข้อ 2 Tests: รับ record ใน `docs/reviews/tests/` ที่มี `By: codex` หรือ `By: opencode` ตามกฎเดิม (commit ตรง, working tree สะอาด, ขอบเขต whole suite หรือ since) ตามคำตอบ Q1
- รายงาน review ทุกฉบับมี `Reviewer:` (claude, codex, opencode) และ `Author:` ซึ่งได้จากชื่อ branch (`agent/<tool>/…`) หรือคำของผู้ใช้ รายงานที่ Reviewer เท่ากับ Author จะไม่นับเป็นเงื่อนไข merge ตามคำตอบ Q2
- requirement §13: จาก "`/mflow:*` ใช้ได้เฉพาะใน Claude Code" เป็น "ยกเว้น test และ review ซึ่งมีเป็น skill ใน `.agents/skills/` ให้ Codex และ OpenCode"
- README:90, manual:498 และ FR-15 ที่เขียนว่า "Codex ไม่มี hook" เปลี่ยนเป็น "hook ของ mflow ทำงานเฉพาะใน Claude Code" (Codex 0.162 มี hook แล้ว แต่ mflow ไม่ได้ใช้)
- help: แถว "รัน test หรือรีวิวด้วย Codex/OpenCode"
- ทะเบียน tool ใน `lib.mjs` ไม่เปลี่ยน (`/mflow:delegate` ยังใช้ได้เหมือนเดิม)

## 7. คำถามที่ต้องตัดสินก่อนสร้าง

### Q1 ผล test ที่ Codex หรือ OpenCode รัน นับเป็นหลักฐานให้ `/mflow:review` ของ Claude ไหม
- ก. นับ ถ้าเป็นไปตามกฎเดิมทุกข้อ และมี `By:` บอกว่าใครรัน
- ข. ไม่นับ Claude ต้องรันเอง (`/mflow:test since`)
- **Claude แนะนำ:** ก. กฎเดิมตรวจได้จากไฟล์และ git อยู่แล้ว และเป็นเหตุผลหลักที่อยากให้เครื่องมืออื่นรัน test
- **ถ้าผิด:** Claude อนุมัติ merge จากผล test ที่ตัวเองไม่ได้เห็นรัน ถ้าเครื่องมืออื่นบันทึกผิด bug จะหลุดเข้า main แก้ทีหลังได้ (revert) แต่เสียเวลา

### Q2 รายงาน review ของ Codex หรือ OpenCode ใช้เป็นเงื่อนไข merge ได้ไหม
- ก. ได้ เมื่อคนรีวิวไม่ใช่คนเขียน (Reviewer ≠ Author) ตรวจจากรายงานได้
- ข. ไม่ได้ เป็นความเห็นเสริมเท่านั้น `/mflow:review` ของ Claude ยังเป็นตัวตัดสิน
- **Claude แนะนำ:** ก. คนรีวิวที่ไม่ใช่คนเขียนคือประโยชน์หลัก และกฎ Reviewer ≠ Author กันกรณีเครื่องมือรีวิวงานของตัวเอง
- **ถ้าผิด:** โค้ดที่ผ่านรีวิวของเครื่องมือที่ตรวจไม่ละเอียดเท่า จะเข้า main ได้

### Q3 แก้ requirement §13 ให้มีข้อยกเว้นสองคำสั่งนี้
- ก. ใช่ เฉพาะ test และ review คำสั่งอื่น (analyze, discuss, apply ฯลฯ) ยังเป็นของ Claude
- ข. ใช่ และเปิดทางให้คำสั่งอื่นตามมาในภายหลัง
- **Claude แนะนำ:** ก. เริ่มจากสองคำสั่งที่ต้องการจริง แล้วค่อยขยายเมื่อใช้แล้วได้ผล
- **ถ้าผิด:** แก้ข้อความใน requirement ทีหลังได้ ไม่มีต้นทุน

### Q4 `e2e` นอก Claude Code
- ก. ไม่รองรับ: `$mflow-test e2e` ตอบว่าให้ไปรันใน Claude Code
- **Claude แนะนำ:** ก. ที่นี่ไม่มี hook `e2e-guard` ที่จำกัดจำนวน browser และการรัน Playwright ทั้งชุดเคยทำให้เครื่องดับมาแล้ว
- **ถ้าผิด:** ถ้ารองรับโดยไม่มีตัวกัน เครื่องอาจดับระหว่างรัน

### Q5 ที่เก็บ script ของ mflow-review
- ก. ในโฟลเดอร์ของ skill เอง (`mflow-review/scripts/`) แต่ละ skill ครบในตัว
- ข. โฟลเดอร์กลางที่ skill ทั้งสองใช้ร่วมกัน
- **Claude แนะนำ:** ก. ตอนนี้มีแค่ mflow-review ที่ใช้ script และ skill ที่ครบในตัวย้ายหรือลบได้ทั้งโฟลเดอร์
- **ถ้าผิด:** ถ้าต่อไปมีหลาย skill ใช้ script เดียวกัน จะมีสำเนาซ้ำ ย้ายไปโฟลเดอร์กลางทีหลังได้

## 8. การทดสอบ

- `tests/agent-skills.test.mjs`: ไม่เหลือ `${CLAUDE_PLUGIN_ROOT}`, ชื่อและ description ผ่านกฎของ OpenCode, frontmatter ไม่มี field อื่นระดับบน, `agents/openai.yaml` มี `allow_implicit_invocation: false`, ไม่เขียนทับโฟลเดอร์ที่ไม่มี marker, ไม่เขียนผ่าน link ที่ชี้ออก, รันซ้ำไม่เขียน, `discuss.mjs checks` รันได้จากตำแหน่งที่คัดลอกไป
- doctor: เตือนเมื่อ marker เก่า
- ทดสอบจริงกับ Codex 0.162.1 ในโปรเจกต์จำลอง (temp): `codex exec` เรียก `$mflow-test` แล้วได้ record ที่มี `By: codex`
- OpenCode: CLI ไม่อยู่ใน PATH ของเครื่องนี้ จึงตรวจได้แค่ตามเอกสาร ต้องให้ผู้ใช้ลองเอง

## 9. ความเสี่ยงและข้อจำกัด

- **OpenCode ยังไม่ได้ลองจริง** รองรับตามเอกสาร opencode.ai/docs/skills
- **รูปแบบ skill ของ Codex และ OpenCode อาจเปลี่ยนตามรุ่น** marker เวอร์ชันและ doctor ช่วยให้รู้ตัว
- **เครื่องมืออื่นทำตาม skill ได้ดีแค่ไหนยังไม่รู้** ลองกับงานเล็กก่อน
- **sandbox ของ Codex:** test ต้องใช้ `workspace-write` และขั้น restore package อาจต้องมี network
- **สำเนาสองชุดอาจคลาดกัน** แก้ด้วยการสร้างใหม่ทุกครั้งที่ init และ test ที่เทียบกับต้นฉบับ
